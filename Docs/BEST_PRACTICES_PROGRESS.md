## Воспроизведение

```powershell
./.venv/Scripts/python.exe -X utf8 scripts/verify_best_practices.py
./.venv/Scripts/python.exe -X utf8 scripts/build_best_practices_skill.py --check-deployed
./.venv/Scripts/python.exe -X utf8 -m pytest tests/test_best_practices_registry.py -q -p no:cacheprovider
```

После канонической правки: `verify_best_practices.py --write-docs`, затем
`build_best_practices_skill.py --write --deploy --check-deployed`.
Установщик проверяет владение по манифесту и сохранность старых хешей перед
записью; неизвестные и локально изменённые файлы не перезаписывает.
Защищённый каталог .agents может требовать разрешённого повышения доступа.
Обычная среда pytest использует свой temp; для Windows sandbox нужен новый
изолированный basetemp с заранее проверенной принадлежностью workspace.

## Следующая зависимость

После первого коммита `725a1ca` подготовка уточнена по предметным API-разделам.
`EvaluateAll` не различает общий успех/отказ своим возвратом; `Status` относится
к последней операции и читается сразу после индексного обращения. Единицы
`Value` на странице не заданы. Для native-пилота предложен полный протокол:
контролируемый активный граф → paired reads → независимые размеры → rebuild
и полный shape → сохранение/новые ссылки → повторное изменение W.
Эта документация меняет будущие критерии приёмки, но не реализует вызовы.

[PLAN.md](../PLAN.md) сохраняет стадию1 открытой: L3 и S1-B1…S1-B5 ещё требуют
завершения и итоговой same-wheel цепочки. L3/native-сессию ведёт другой чат.
Текущая работа не вмешивается в его COM-сессию и не расширяет gates стадии1.

Для нового пилота требуется формальный переход к стадии2. После него следует
сверка минимальных API → доменный метод и MCP-фасад → полное чтение выражений
и тела с двумя отверстиями → lifecycle/handles/checkpoint → точный dev-wheel
и приёмка W100→140→save/reopen→120. Исходные координаты и фиксированный массив
не заменяют зависимость от W. Принятие детали не подтверждает устойчивость сборок.

Изменения группируются в локальный Git-коммит. Отдельный push/Actions ради
этого пакета документации и навыка не выполняется; пакетная отправка следует
основному процессу проекта.
