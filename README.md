# SolidWorks MCP — форк babkin-kd

MCP-сервер для создания и редактирования моделей в локальном SOLIDWORKS. Этот форк развивает [исходный проект hjbaard/SolidWorks-MCP](https://github.com/hjbaard/SolidWorks-MCP) под инженерные задачи: параметрические детали, листовой металл, чертежи, сварные конструкции и сборки.

**Проект находится в разработке.** API v2 переносится и проверяется по стадиям; полный набор возможностей исходного сервера не объявляется готовым в v2. Рабочая установка v1 сохраняется отдельно. Наш v2 пока не опубликован в PyPI или MCP Registry.

## Что меняется в нашем форке

- Явный выбор документа, конфигурации и объекта вместо зависимости от случайного активного документа или выделения.
- Устойчивые ссылки на тела, грани, рёбра и элементы дерева; проверка принадлежности и актуальности объекта.
- Проверяемые изменения: ревизия перед записью, чтение результата, перестроение и контроль постусловий.
- Один STA-поток для CAD и постоянный журнал заданий SQLite. Тайм-аут ожидания не означает отмену COM; неопределённая операция не повторяется автоматически.
- Осмысленные русские названия новых деталей, компонентов и элементов дерева.
- Максимальное повторное использование стандартных изделий из Toolbox, корпоративных библиотек и PDM. Библиотечные файлы, артикулы и обозначения стандартов сохраняются.
- Поддержка пользовательских K-факторов и шаблонов чертежей ЕСКД/ГОСТ входит в основной план разработки.

## Текущий статус

| Область | Состояние |
| --- | --- |
| Опубликованный кандидат API v2 в `stage-1-fixes` | Диагностика, журнал заданий, явное чтение документов и геометрии деталей, непрозрачные ссылки |
| Последующие локальные кандидаты | Переименование, размеры, измерения, создание детали и базового выдавливания развиваются и проходят отдельную приёмку |
| Листовой металл, чертежи, сварные конструкции, сборки и PDM в v2 | Планируются и переносятся по стадиям; наличие legacy-кода не означает готовность публичных инструментов |
| Кинематика, сетки/3D-печать и Simulation | Дополнительный функционал третьей стадии |

Локальные кандидаты могут опережать опубликованную ветку. Точный каталог выбранной версии определяется через `tools/list` и `system_get_info`; контракт и границы проверок описываются для конкретной сборки. Успех одного теста или CI не означает приёмку всех CAD-операций.

## Приоритеты и три стадии

1. **Исправление.** Безопасная основа API v2, явные документы и объекты, размеры, перестроение, восстановление после ошибок и перенос базовых операций моделирования.
2. **Основной функционал.** Детали → листовой металл → чертежи → базовые сборки с библиотечными стандартными элементами → сварные конструкции. Далее — расширенные конфигурации, большие сборки и SOLIDWORKS PDM Professional.
3. **Дополнительный функционал.** Кинематика и зазоры, подготовка к 3D-печати и работа с сетками, статическая прочность сборок с контактами в Simulation, дальнейшее развитие файлового обмена.

**Импорт и экспорт файлов имеют низкий приоритет:** их дальнейшее развитие не блокирует первые две стадии. DXF развёртки и PDF чертежа реализуются в необходимом объёме вместе с соответствующим производственным сценарием. Обычное открытие и сохранение нативных документов остаётся базовой функцией.

План и критерии приёмки: [PLAN.md в ветке разработки](https://github.com/babkin-kd/SolidWorks-MCP/blob/stage-1-fixes/PLAN.md). Последние решения и результаты сначала фиксируются локально, затем публикуются связанным пакетом. Задачи: [Issues](https://github.com/babkin-kd/SolidWorks-MCP/issues), стадии: [Milestones](https://github.com/babkin-kd/SolidWorks-MCP/milestones).

## Требования и подключение

- Windows с установленным, лицензированным и запущенным SOLIDWORKS.
- Целевая проверочная среда форка — **SOLIDWORKS 2023 SP2.1**. Поддержка иных версий требует собственной проверки.
- Python 3.11+; отдельное окружение для разработки v2.
- MCP-клиент с поддержкой stdio.

Установите wheel выбранного проверенного кандидата в отдельное dev-окружение. Для проверки установленного пакета не используйте `PYTHONPATH` исходников. Не заменяйте рабочую установку v1 экспериментальной сборкой.

Точка входа:

```powershell
solidworks-mcp-v2 --state-dir "C:\CAD\MCP-State"
```

Каталог состояния должен быть постоянным и приватным: в нём хранится журнал заданий. Сервер подключается к уже запущенному SOLIDWORKS.

Пример конфигурации MCP-клиента после установки wheel:

```json
{
  "mcpServers": {
    "solidworks-v2": {
      "command": "C:\\CAD\\SolidWorks-MCP\\.venv\\Scripts\\solidworks-mcp-v2.exe",
      "args": ["--state-dir", "C:\\CAD\\MCP-State"]
    }
  }
}
```

Замените пути на свои. Сначала вызовите `system_get_info` и проверьте версию, происхождение сборки и доступные инструменты. Каталог экспорта, если он нужен для поддержанной операции, задаётся оператором отдельно через `--output-dir`.

Команда `uvx solidworks-mcp` устанавливает пакет исходного проекта, **а не наш кандидат v2**.

## Правила проверки и разработки

- `main` сохраняется стабильным; первая стадия ведётся в `stage-1-fixes`. Изменения проходят PR в этот форк.
- Связанные изменения проверяются локально и публикуются пакетом, чтобы экономить GitHub Actions.
- Различаются pure-тесты, проверка установленного wheel и фактические native-операции в SOLIDWORKS. Пропущенный native-тест не считается пройденным.
- Новые CAD-функции публикуются после приёмки своего поддержанного сценария; лицензируемые PDM/Simulation не объявляются доступными заранее.
- Реальные CAD-файлы, корпоративные шаблоны, локальные PDM-данные, секреты и журналы заданий остаются вне публичного Git.
- Рабочая v1 и dev v2 не должны одновременно изменять одну CAD-сессию без общего координатора.
