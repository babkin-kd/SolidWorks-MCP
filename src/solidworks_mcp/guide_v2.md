# SolidWorks MCP — контракт v2 в разработке

Это отдельная точка входа `solidworks-mcp-v2 --state-dir <постоянный локальный каталог>`.
Рабочая установка v1 остаётся отдельно. В этом кандидате реализованы журнал заданий
и явное чтение метаданных документов/геометрии деталей; операции моделирования ещё переносятся.
Полный план развития находится в `PLAN.md`. Первый рабочий выпуск для моделирования
включает геометрию и изготовление, как указано в плане.

## Доступные инструменты

| Инструмент | Результат |
| --- | --- |
| `system_get_info` | Версии API/пакета/схемы/SDK, hash каталога инструментов, данные сборки и фактические возможности |
| `job_get` | Состояние и данные задания по `operation_id`, включая поздний результат |
| `job_list` | Постраничный список заданий; оба поля курсора передаются вместе |
| `job_cancel` | Атомарная отмена задания в очереди; исполняемое задание не отменяется |
| `document_list` | Открытые документы: непрозрачные ID, конфигурации, метаданные, токены наблюдаемого состояния |
| `document_get` | Метаданные явного документа и существующей конфигурации без их активации |
| `body_list` | Страница твёрдых/поверхностных тел явной детали; непрозрачные `object_id` |
| `face_list` | Страница граней заданного `body_id`, площадь в мм² и тип поверхности |
| `edge_list` | Страница рёбер заданного `body_id`, длина и концы в мм |
| `geometry_get` | Восстановление тела/грани/ребра по зарегистрированному `object_id` |

Опрос журнала не требует доступа к SolidWorks и не ждёт занятого STA-потока.
Инструмент выполнения произвольного кода или произвольного имени CAD-метода не предоставляется.
Чтение документа — задание на единственном STA-потоке. Его `request_id` обязателен;
новый снимок требует нового ID. Повтор возвращает исторический результат прежнего
задания, даже если модель уже изменилась. `timeout_s` от 0 до 120 задаёт только время
ожидания; при `queued`/`running` опрашивайте `job_get` по возвращённому `operation_id`.
Данные завершённого чтения находятся в `data`, а при опросе `job_get` — в `data.result`.

Сначала вызовите `document_list`, затем передайте полученные `document_id` и точное
имя конфигурации в `document_get`. Пустое имя допустимо лишь для документа без
конфигураций. Нет автоматического выбора активного документа или первого тела.
Чтение не переключает конфигурации, не перестраивает и не сохраняет документы,
не меняет видимость SolidWorks и не раскрывает lightweight-компоненты сборки.
ID относятся к текущему соединению: после перезапуска сервера список нужно получить
заново. Исторические ID в завершённых заданиях не становятся актуальными от их чтения.

`observation_revision` покрывает только update stamp и метаданные документа:
заголовок, путь, конфигурации, флаг сохранения и наблюдаемый счётчик изменений.
Неизменный токен не доказывает неизменность всех свойств, операций или материалов;
изменение и возврат между наблюдениями могут остаться незамеченными. Это ещё
не `expected_revision` для мутаций. Доступ к геометрии неактивной конфигурации
и изменения моделей этим кандидатом не предоставляются.

## Чтение геометрии

Для геометрии передайте явные `document_id`, активную `configuration` и текущий
`expected_observation_revision` из `document_get`/`document_list`. Это проверка
согласованности чтения, **не полный expected_revision для будущих мутаций**.
Неактивная конфигурация, другая ревизия наблюдения и необходимость перестроения
отклоняются до перечисления геометрии. Только детали; геометрия экземпляров сборок,
координаты компонента и чтение неактивной конфигурации ещё не приняты.

`body_list` принимает `body_type=all|solid|surface` и включает скрытые native-тела.
`all` означает твёрдые и поверхностные тела, не сеточные/графические/проволочные.
Полученный `object_id` тела передаётся как `body_id` в `face_list`/`edge_list`.
Геометрические ID принадлежат документу и конкретному объекту конфигурации. Они
восстанавливаются через native persistent references и проверяются на принадлежность
родительскому телу. Удалённая, подавленная, чужая или неверная ссылка не заменяется
первым телом/индексом. Проверяется фактическое присутствие тела и топологии в
активной конфигурации: native status=OK сам по себе этого не доказывает.
Пересоздание одноимённой конфигурации не восстанавливает её
старые ссылки. После закрытия документа/перезапуска MCP нужны новые ID.

Native persistent ID не передаётся клиенту. Сериализация ID может измениться после
перестроения; сравнение выполняется через API SolidWorks. Для того же native-объекта
возможно несколько непрозрачных ID; каждый остаётся связан с исходной ссылкой.
Переименование не используется для поиска объекта. Без native persistent reference
операция возвращает ошибку, а не менее надёжный индекс.

Списки принимают `limit=1..200`, возвращают `items`, `total_count`, `next_cursor`.
Следующая страница требует нового `request_id`, того же контекста и курсора.
Курсор привязан к исходному перечислению, запросу и ревизии; его нельзя переносить
между телами/типами объектов или использовать после изменения документа. Размер
ответа ограничен страницей; native API всё ещё перечисляет полную коллекцию.
Бюджеты на документ: 100000 объектов в коллекции/снимках страниц, 100000 ссылок,
10000 курсоров; превышение — явная ошибка. Снимки удерживаются только в STA и не
попадают в SQLite. Они освобождаются при закрытии документа, обнаружении новой
ревизии или серверном shutdown; старые ссылки не переигрываются автоматически.

Все координаты остаются в системе модели, длины — мм, площади — мм². Bounding box
тела помечен `approximate=true`: он не является точным метрологическим измерением.
Поверхностное тело не получает выдуманного объёма или массы.

## Ответы и задания

Ответ содержит `status`, `operation_id`, `context`, `data`, `diagnostics`, `error`.
Для `job_get` статус относится к самому заданию; для списка/отмены — к запросу
наблюдения, а состояние задания находится в `data`. Отказ отменить уже исполняемое
задание виден как `data.cancelled=false`; это не остановка COM-операции.

Состояния: `queued`, `running`, `succeeded`, `failed`, `cancelled`, `unknown`.
`request_id` однозначно связан с операцией, аргументами и контекстом. Повтор
идентичного запроса возвращает прежний результат, тот же ID с другими аргументами
отклоняется. Истечение времени ожидания и отмена ожидания не отменяют само задание.
Мутация требует проверки постусловий. Непроверенный результат или неожиданная
ошибка после возможного изменения получают `unknown`, а не ложное подтверждение успеха.

SQLite-журнал использует атомарные переходы состояний и эксклюзивное владение
на уровне ОС. Второй процесс не может сбросить задания живого владельца. После
аварийного завершения `queued`/`running` становятся `unknown`, завершённые результаты
сохраняются. Никакие записанные операции автоматически не повторяются.
`failed` после изменения допустим только при подтверждённом неизменном состоянии
или проверенном откате; проверку и восстановление выполняет доменный CAD-слой.

Сохраняйте каталог состояния между запусками. В нём могут быть локальные пути
документов и данные операций; не публикуйте его в GitHub. Полные ревизии для изменений,
устойчивые ссылки геометрии и блокировка документа после неопределённого изменения
ещё реализуются в рамках первой стадии.

## Общие правила будущих CAD-инструментов

Новые детали и элементы дерева имеют осмысленные русские названия. Стандартные
изделия выбираются из утверждённых Toolbox/корпоративных/PDM-библиотек; исходные
файлы, обозначения стандартов и технические идентификаторы сохраняются. Единицы
контракта: мм, градусы, кг. Документ, конфигурация и выбранный объект указываются явно.
