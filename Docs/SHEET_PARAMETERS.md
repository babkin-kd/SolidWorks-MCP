# Параметры существующего листового L-профиля

Принятый блок dev63: `sheet_prepare_parameters` и `sheet_set_parameters`, scope
`single_l_sheet_parameters_v1`. На одном установленном wheel: 3545 pure passed /
323 CAD deselected, metadata44/15, internal native8/public MCP10, accepted=true.

Оба инструмента требуют явные документ, конфигурацию и объект базового сгиба,
а также все три значения: толщину в мм, внутренний радиус в мм и пользовательский
K-фактор. Запись дополнительно требует ревизию и request_id. Подготовка только
читает модель; изменение выполняется после durable checkpoint и захвата guard.

Домен описывает один самостоятельный native L-профиль с одним сгибом 90°,
одним телом и конфигурацией, в согнутом или развёрнутом состоянии. Native-приёмка
записи dev63 выполнена на согнутом профиле; последующие развёртка/сгиб с новыми
параметрами приняты. Прямое изменение уже развёрнутого профиля проверено
искусственными сценариями, но ещё требует отдельной native-приёмки. Исходные
полки, длина, полностью определённый эскиз, состояние flat/fold, имена и остальные
параметры сохраняются. Значения по умолчанию для K отсутствуют. Таблицы гибов,
параметры от материала, произвольные профили и многотельные детали не входят
в этот scope. Инструмент редактирует существующие узлы, не создаёт их заново.

Ревизия охватывает два полных замыкающих снимка: эскиз и размеры, полную BREP,
native-параметры, fixed-face, persistent-ссылки тела и членов дерева,
template/default allowance, параметры relief и gauge. После изменения заново
проверяется полная аналитически ожидаемая форма, а не только объём или габариты.
K дополнительно проверяется в native allowance; его геометрическое действие
подтверждается физической развёрткой.

Изменение выполняется через точный `TemplateSheetMetal`, полученный
`IModelDocExtension.GetTemplateSheetMetal` и сверенный с уже доказанным членом
дерева: `AccessSelections`, изменение t/r и `ICustomBendAllowance`,
`ModifyDefinition`, перестроение. При подтверждённом отказе доступ освобождается;
неопределённый исход не считается отменой и не повторяется автоматически.
Известный сбой допускает восстановление только из полностью доказанного
исходного или намеренно изменённого состояния; чужое промежуточное состояние
оставляется для reconciliation. Исходные русские имена возвращаются только
после доказательства принадлежности и полного перехода параметров.

`GetUseGaugeTable` читается у точного template: нужны код 0 и отключённая таблица.
В source-пробе body SheetMetal возвращал код 2, template — код 0. Код 2
не принят за успех. Имя файла при отключённой таблице не определяет её статус.
Основные первичные источники — установленная справка SOLIDWORKS API
(`GetTemplateSheetMetal`, пример `Get Template Sheet Metal Feature Data`,
`GetUseGaugeTable`, `swSheetMetalModifierError_e`) и
[члены ISheetMetalFeatureData](https://help.solidworks.com/2024/English/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.ISheetMetalFeatureData_members.html).

## Доказательства разработки

На реальной контрольной модели выполнена source-цепочка: создание профиля
40×20×30 мм, t=2/r=2/K=0,42 → t=2,5/r=3,5/K=0,38 → физическая развёртка →
обратный сгиб → исходные параметры. Все шесть заданий succeeded/committed,
исходное состояние восстановлено, свои документы закрыты. Это проверка исходников,
а не приёмка установленного кандидата. Пробы и журналы находятся в private work/;
первая неуспешная read-проба сохранена отдельно.

Искусственные тесты проверяют независимые folded/flat формы, неизменность опций
и членов модели, строгие аргументы, checkpoint/guard, scoped restoration,
неопределённые исходы COM и MCP-контракт. Они не заменяют CAD-приёмку.
