# Диагностика времени — кандидат dev69 стадии 1

`diagnostics_get_timings` реализован в исходниках. До проверки точного
установленного wheel это не installed/native-приёмка. Стадия 1 остаётся открытой;
текущая матрица требований — [STAGE_1_REQUIREMENTS_MATRIX.md](STAGE_1_REQUIREMENTS_MATRIX.md).

## Контракт

Локальный инструмент принимает `period_s` (положительное число, максимум
31 сутки), `operation` (имя зарегистрированного инструмента либо доменной
операции), `kind` (`job`, `mcp_call`, `poll`). Возвращает обычный ResponseEnvelope,
количество завершённых замеров, медиану, p95 с линейной интерполяцией, размер
выборки и этапы, отсортированные по медиане. Сборки, операции, типы вызовов,
фиксированные серверные сценарии и исходы не смешиваются.

Инструмент не ставит CAD-задание в очередь и не измеряет сам себя. Пустая
выборка не означает нулевую длительность. Отмена ожидания MCP имеет собственный
исход `cancelled`; физическое задание продолжает выполняться и получает отдельный
замер после своего фактического завершения. Повтор request_id и опрос job_get
не создают второй замер CAD-операции. Интервалы `queued`/`running` публичного
вызова не объявляются завершением задания.

## Включение и хранение

Сбор по умолчанию выключен: дополнительных файлов и обращений к часовому
источнику нет. Оператор включает его аргументами console entry point:

```text
solidworks-mcp-v2 --state-dir <приватный каталог> --enable-timings
  --timings-max-records 1000 --timings-retention-days 7 --timings-max-mib 16
```

Границы: 1–10000 записей, 1–31 сутки, 1–64 MiB для файла базы. SQLite rollback
journal временно занимает дополнительное место. Записи удаляются по возрасту
и количеству при записи, чтении и открытии хранилища. SQLite page cap ограничивает
размер базы; уже существующую базу выше нового лимита инструмент считает
недоступной, сохраняя её содержимое.

`timings.sqlite` хранится отдельно от обязательного `jobs.sqlite`, внутри
приватного state-dir, вне Git. Он содержит только серверные идентификаторы,
публичную идентичность сборки, исходы и интервалы. Аргументы, request_id, пути,
имена CAD-документов/конфигураций, геометрия и текст ошибок не копируются.
Ошибка необязательной диагностики увеличивает счётчики потерянных записей;
она не меняет статус задания, durable checkpoint или hold. Отключать обязательный
журнал нельзя. Включение требует совпадения установленного пакета с build manifest.

## Что именно измерено

Источник длительности — `perf_counter`, Unix wall time используется только
для фильтра периода/retention. Для job начало — перед отправкой созданного
задания worker, конец — фактический terminal/неопределённый исход. Первоначальная
запись создания job до dispatch не входит в этот интервал; записи start,
checkpoint, verification и finish измеряются отдельно. Для MCP-вызова измеряется
время выполнения серверной функции. Стенд отдельно измеряет транспортное время
клиента, включая необязательную запись диагностики; оно не подменяет серверный
интервал. Сбой процесса до окончания trace не получает выдуманную длительность
после рестарта: журнал восстанавливает состояние, timing sample остаётся отсутствующим.

Подключены очередь, prepare, read_bundle, validate, apply_bundle, postconditions, restoration
и запись журнала. Read-only подготовка измеряется как prepare, другое чтение
как read_bundle; эти интервалы не подменяют COM. Первичная запись создания
задания измеряется в публичном MCP trace, последующие записи — в job trace.
`apply_bundle` может включать вложенную проверку/COM/перестроение.
Вложенные интервалы inclusive пересекаются: их нельзя складывать для получения
общего времени. Отдельно возвращаются exclusive-интервалы и число измеренных
интервалов. Неизмеренная работа остаётся частью общего времени.

COM coverage ограничен явно обёрнутыми вызовами: GetDocuments, InsertSketch и
FeatureExtrusion3 базового прямоугольника, SetSystemValue3 и ForceRebuild3 общего
адаптера размеров. `rebuild` содержит именно ForceRebuild3; проверка результата
остаётся в обычном контуре. Это не полный census всех COM-dispatches. Имена
методов и параметры в журнал не записываются, дополнительных COM-вызовов нет.
Сценарий пока `unclassified_v1`: он отделяет широкую область, но не утверждает
поддержку всех типов геометрии. Полный счётчик COM и группировка инженерных
сценариев остаются предметом S1-18/S1-21.

## Проверки кандидата

- Pure: реальные SQLite/ThreadPool гонки timeout/replay/cancellation, ошибки
  дополнительного хранилища, verified restoration/unknown hold, nested intervals,
  фильтры/статистика, приватность, retention/count/page cap и schema без CAD.
- `scripts/verify_timings_v2.py`: installed stdio, enabled/disabled, точные
  build/version/digest, counts и фильтры, отдельный замер транспортных расходов.
- Тот же стенд с `--run-solidworks`: только 10 read-only document_list на пустой
  свободной сессии в каждом режиме; контроль baseline и реальных GetDocuments
  интервалов. Не создаёт и не закрывает моделей. Supervisor ждёт завершения
  фактического задания, тайм-аут не отменяет COM.

Installed/native-результаты и размер измеренной выборки должны быть добавлены
после выполнения стенда. Проверка пустой сессии не закрывает итоговые N0–N6,
геометрические workload benchmarks или всю строку S1-18/S1-19/S1-20.
