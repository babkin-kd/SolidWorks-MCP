# SolidWorks MCP — контракт v2 в разработке

Это отдельная точка входа `solidworks-mcp-v2 --state-dir <постоянный локальный каталог>`.
Рабочая установка v1 остаётся отдельно. В этом кандидате реализованы журнал заданий
и явное чтение метаданных документов/геометрии/элементов деталей, проверяемое
переименование элемента, изменение поддерживаемого размера и экспорт детали;
остальные операции моделирования ещё переносятся.
Полный план развития находится в `PLAN.md`. Первый рабочий выпуск для моделирования
включает геометрию и изготовление, как указано в плане.

## Доступные инструменты

| Инструмент | Результат |
| --- | --- |
| `system_get_info` | Версии API/пакета/схемы/SDK, hash каталога инструментов, данные сборки и фактические возможности |
| `job_get` | Состояние и данные задания по `operation_id`, включая поздний результат |
| `job_list` | Постраничный список заданий; оба поля курсора передаются вместе |
| `job_cancel` | Атомарная отмена задания в очереди; исполняемое задание не отменяется |
| `document_list` | Открытые документы: непрозрачные ID, конфигурации, метаданные, токены наблюдаемого состояния |
| `document_get` | Метаданные явного документа и существующей конфигурации без их активации |
| `body_list` | Страница твёрдых/поверхностных тел явной детали; непрозрачные `object_id` |
| `face_list` | Страница граней заданного `body_id`, площадь в мм² и тип поверхности |
| `edge_list` | Страница рёбер заданного `body_id`, длина и концы в мм |
| `geometry_get` | Восстановление тела/грани/ребра по зарегистрированному `object_id` |
| `feature_list` | Страница полного дерева элементов детали с persistent ID и ревизией области `part_feature_tree_v1` |
| `feature_get` | Восстановление элемента по opaque ID, актуальное имя/тип/состояние и ревизия дерева |
| `feature_rename` | Русское имя заданного элемента с ревизией, checkpoint, проверкой результата и восстановлением имени при ошибке |
| `dimension_list` | Страница размеров детали со значениями в мм/градусах, устойчивыми ссылками, ограничениями записи и ревизией `part_dimension_values_v1` |
| `dimension_get` | Чтение явно указанного размера с проверкой native identity и принадлежности владельцу |
| `dimension_set_value` | Изменение независимого размера элемента с проверкой ревизии, rebuild, readback и подтверждённым восстановлением при ошибке |
| `export_prepare` | Read-only проверка явной детали и параметров экспорта; возвращает ревизию `part_solid_brep_export_v1` |
| `export_part` | STL/STEP/Parasolid без перезаписи файла, с проверкой исходной модели, настроек и манифестом результата |

Опрос журнала не требует доступа к SolidWorks и не ждёт занятого STA-потока.

Схема журнала 3 сохраняет внутренние checkpoint изменений и блокировки неопределённого
состояния. Если у задания есть checkpoint, `job_get`/`job_list` добавляют поле `mutation`:
цель, состояние до записи, фазу и свидетельство проверки/согласования. После аварии
неподтверждённое изменение не повторяется. Переподключение не снимает блокировку.
Схема 3 сохраняет доверенную область побочных эффектов. Неопределённые изменения
общих настроек приложения блокируют записи во все документы; переход из схем 1/2
сохраняет задания. Старый runtime схемы 2 не должен открывать этот новый журнал.
Протокол подключён к `feature_rename`, `dimension_set_value` и `export_part`.
Диагностика указывает `cad_mutations=true` и точный список
`implemented_mutations=["feature.rename", "dimension.set_value", "export.execute"]`.
Создание деталей и клиентская команда снятия блокировки ещё не предоставляются.
Инструмент выполнения произвольного кода или произвольного имени CAD-метода не предоставляется.
Чтение документа — задание на единственном STA-потоке. Его `request_id` обязателен;
новый снимок требует нового ID. Повтор возвращает исторический результат прежнего
задания, даже если модель уже изменилась. `timeout_s` от 0 до 120 задаёт только время
ожидания; при `queued`/`running` опрашивайте `job_get` по возвращённому `operation_id`.
Данные завершённого чтения находятся в `data`, а при опросе `job_get` — в `data.result`.

Сначала вызовите `document_list`, затем передайте полученные `document_id` и точное
имя конфигурации в `document_get`. Пустое имя допустимо лишь для документа без
конфигураций. Нет автоматического выбора активного документа или первого тела.
Чтение не переключает конфигурации, не перестраивает и не сохраняет документы,
не меняет видимость SolidWorks и не раскрывает lightweight-компоненты сборки.
ID относятся к текущему соединению: после перезапуска сервера список нужно получить
заново. Исторические ID в завершённых заданиях не становятся актуальными от их чтения.

`observation_revision` покрывает только update stamp и метаданные документа:
заголовок, путь, конфигурации, флаг сохранения и наблюдаемый счётчик изменений.
Неизменный токен не доказывает неизменность всех свойств, операций или материалов;
изменение и возврат между наблюдениями могут остаться незамеченными. Это ещё
не `expected_revision` для мутаций. Чтение геометрии неактивной конфигурации ещё
не предоставляется; для геометрических изменений эта ревизия не используется. Переименование элемента
требует отдельной ревизии дерева из `feature_list`/`feature_get`.

## Дерево элементов и переименование

Только детали и явная активная конфигурация, без активации/перестроения/сохранения.
Дерево включает поглощённые подэлементы. Ревизия `part_feature_tree_v1` учитывает
ID открытия/соединения и конкретной конфигурации, document update stamp и метаданные,
полное дерево имён/типов/владельцев/подавления/ошибок, счётчик native-уведомлений и
собственный счётчик попыток записи. Дерево ограничено 5000 элементами; при превышении
выдаётся ошибка, неполной ревизии нет. Страницы 1–200 элементов привязаны к ревизии.
Native `GetID` нужен только для обхода/сопоставления диагностики, не для восстановления
клиентского объекта. `object_id` восстанавливается через persistent reference и проверяется
на присутствие в текущем дереве. Узлы без корректной native persistent reference имеют
`object_id=null` и `reference_error`; неверная ссылка не заменяется поиском по имени или ID.

Это объявленная область ревизии для переименования, не обещание охвата произвольных
данных сторонних модулей, всех визуальных свойств или внешних файлов. `ModifyNotify`
сообщает первое загрязнение документа и не заменяет снимок/другие уведомления. Новые
операции обязаны расширить свою область защиты. COM-поток обрабатывает сообщения;
native-обработчики только увеличивают счётчик, без reentrant CAD-вызовов.

Повторная проверка и setter — отдельные native-вызовы внутри одноразового UI guard.
После durable checkpoint уровня приложения native `Lock` должен подтвердить
состояние 2, после операции/проверенного отката `UnLock` — состояние 0. В журнале
сохраняются наблюдения `execution_guard`; неопределённое освобождение запрещает
последующие записи во все документы. UI lock блокирует интерактивное редактирование;
общая блокировка сторонних COM-клиентов/add-ins не гарантируется. Счётчик событий
не доказывает атомарность.

Перед `feature_rename` получите свежие `object_id`/`revision`; передайте их как
`object_id`/`expected_revision`, а также `request_id`, документ, конфигурацию и русское
`name`. Проверка выполнится ещё раз на STA после checkpoint и перед первой записью.
Чужая/удалённая ссылка, другая конфигурация, устаревшая ревизия, необходимость
перестроения, подавленная цель, занятое/недопустимое имя отклоняются. Имя читается после
записи; остальное дерево/ошибки/stamp должны совпасть с ожидаемой областью. Ранее
существовавшие ошибки не объявляются новыми. При ошибке восстанавливается конкретное
имя; чужое новое имя не перезаписывается. Неподтверждённое восстановление сохраняет
блокировку, а чтение/опрос доступны. Это не полный Undo документа или восстановление
его флага сохранения. После `timeout_s=0` опрашивайте `job_get`; повтор того же запроса
не делает вторую запись и возвращает историческое задание.

## Чтение геометрии

Для геометрии передайте явные `document_id`, активную `configuration` и текущий
`expected_observation_revision` из `document_get`/`document_list`. Это проверка
согласованности чтения, **не полный expected_revision для будущих мутаций**.
Неактивная конфигурация, другая ревизия наблюдения и необходимость перестроения
отклоняются до перечисления геометрии. Только детали; геометрия экземпляров сборок,
координаты компонента и чтение неактивной конфигурации ещё не приняты.

`body_list` принимает `body_type=all|solid|surface` и включает скрытые native-тела.
`all` означает твёрдые и поверхностные тела, не сеточные/графические/проволочные.
Полученный `object_id` тела передаётся как `body_id` в `face_list`/`edge_list`.
Геометрические ID принадлежат документу и конкретному объекту конфигурации. Они
восстанавливаются через native persistent references и проверяются на принадлежность
родительскому телу. Удалённая, подавленная, чужая или неверная ссылка не заменяется
первым телом/индексом. Проверяется фактическое присутствие тела и топологии в
активной конфигурации: native status=OK сам по себе этого не доказывает.
Пересоздание одноимённой конфигурации не восстанавливает её
старые ссылки. После закрытия документа/перезапуска MCP нужны новые ID.

Native persistent ID не передаётся клиенту. Сериализация ID может измениться после
перестроения; сравнение выполняется через API SolidWorks. Для того же native-объекта
возможно несколько непрозрачных ID; каждый остаётся связан с исходной ссылкой.
Переименование не используется для поиска объекта. Без native persistent reference
операция возвращает ошибку, а не менее надёжный индекс.

Списки принимают `limit=1..200`, возвращают `items`, `total_count`, `next_cursor`.
Следующая страница требует нового `request_id`, того же контекста и курсора.
Курсор привязан к исходному перечислению, запросу и ревизии; его нельзя переносить
между телами/типами объектов или использовать после изменения документа. Размер
ответа ограничен страницей; native API всё ещё перечисляет полную коллекцию.
Бюджеты на документ: 100000 объектов в коллекции/снимках страниц, 100000 ссылок,
10000 курсоров; превышение — явная ошибка. Снимки удерживаются только в STA и не
попадают в SQLite. Они освобождаются при закрытии документа, обнаружении новой
ревизии или серверном shutdown; старые ссылки не переигрываются автоматически.

Все координаты остаются в системе модели, длины — мм, площади — мм². Bounding box
тела помечен `approximate=true`: он не является точным метрологическим измерением.
Поверхностное тело не получает выдуманного объёма или массы.

## Размеры

Начните с `dimension_list` или `dimension_get`: они возвращают отдельную ревизию
`part_dimension_values_v1`, значения, единицы и причины запрета записи. Ревизия дерева
или наблюдаемого состояния не разрешает изменение размера. Ссылки проверяются по
native identity, persistent reference и присутствию у владельца; имена и порядковые
номера не заменяют устойчивую ссылку. Область ревизии включает полную поддерживаемую
аналитическую геометрию плоских многогранников; неподдерживаемая геометрия отклоняется.

`dimension_set_value` требует активную деталь с одной конфигурацией, независимый
размер элемента, `object_id`, `expected_revision`, `request_id`, `value` и `unit`.
Линейное значение — конечное положительное число в мм; угол — от 0 до 360 градусов
без включения границ. Единицы должны совпасть с типом размера. Размеры эскизов
читаются, но пока не изменяются. Driven, связанные, справочные, управляемые таблицей
размеры и неподдерживаемые зависимости/уравнения явно отклоняются.

После checkpoint инструмент повторно проверяет состояние, записывает значение,
перестраивает целевой документ и проверяет фактическое значение, геометрию и ошибки
элементов. Он не активирует и не сохраняет модель. При ошибке восстанавливается
принадлежащее операции значение; успех восстановления требует отдельной проверки.
Повтор `request_id` не выполняет запись ещё раз. При `unknown` нужно согласование
состояния, автоматический повтор с новым ID запрещён.

## Экспорт детали

Оператор задаёт существующий каталог при запуске:
`solidworks-mcp-v2 --state-dir <журнал> --output-dir <каталог экспорта>`.
`system_get_info.export_output_configured` сообщает наличие этой настройки, без
проверки файловой системы или соединения с CAD. Без настройки оба инструмента
отказывают с `export_output_not_configured` до создания задания или CAD-потока.
Клиент передаёт только простое `filename`; каталог, перезапись и произвольный путь
не являются аргументами инструмента.

`export_prepare` принимает `document_id`, активную `configuration`, `file_format`,
`filename`, `units` и `request_id`. Поддержаны `stl`/`.stl`, `step`/`.step`,
`parasolid`/`.x_t`. Только твёрдые детали в поддерживаемой области плоского
аналитического BREP; сеточные, криволинейные, смешанные и неоднозначные тела
отклоняются. Источник не активируется, не перестраивается и не сохраняется.

Для STL обязательны явные `units=mm|m|in`; единицы отсутствуют в самом файле.
Система координат модели и отрицательные координаты сохраняются, текущая точность
триангуляции сохраняется. Для STEP/Parasolid передайте `units=""`. STEP проверяет
согласованные SI length contexts во всём файле до 4 МиБ; единицы Parasolid не
объявляются проверенными без независимого геометрического roundtrip.

Передайте полученную ревизию как `expected_revision` в `export_part` с теми же
параметрами. Инструмент сохраняет checkpoint, проверяет исходную геометрию и настройки,
восстанавливает собственные временные настройки и публикует один файл без перезаписи.
Манифест содержит размер, SHA-256, систему координат, свидетельства единиц и
`staging_cleanup`. Статус `retained_empty_directory` явно сообщает о собственном
пустом временном каталоге, оставленном после подтверждённой публикации из-за Windows
error 32; его identity и отсутствие файлов проверяются. Другие ошибки не маскируются.
Манифест не подтверждает обратный импорт или полное геометрическое равенство STEP/
Parasolid. Тайм-аут не отменяет COM; результат получают через `job_get`.

## Ответы и задания

Числовые аргументы передавайте числами JSON: строки и `true`/`false` не заменяют
тайм-аут, лимит, значение размера или числовой курсор. Неверный тип отклоняется
при проверке MCP-запроса до запуска CAD; это ошибка аргументов протокола.

Ответ содержит `status`, `operation_id`, `context`, `data`, `diagnostics`, `error`.
Для `job_get` статус относится к самому заданию; для списка/отмены — к запросу
наблюдения, а состояние задания находится в `data`. Отказ отменить уже исполняемое
задание виден как `data.cancelled=false`; это не остановка COM-операции.

Состояния: `queued`, `running`, `succeeded`, `failed`, `cancelled`, `unknown`.
`request_id` однозначно связан с операцией, аргументами и контекстом. Повтор
идентичного запроса возвращает прежний результат, тот же ID с другими аргументами
отклоняется. Истечение времени ожидания и отмена ожидания не отменяют само задание.
Мутация требует проверки постусловий. Непроверенный результат или неожиданная
ошибка после возможного изменения получают `unknown`, а не ложное подтверждение успеха.

SQLite-журнал использует атомарные переходы состояний и эксклюзивное владение
на уровне ОС. Второй процесс не может сбросить задания живого владельца. После
аварийного завершения `queued`/`running` становятся `unknown`, завершённые результаты
сохраняются. Никакие записанные операции автоматически не повторяются.
`failed` после изменения допустим только при подтверждённом неизменном состоянии
или проверенном откате; проверку и восстановление выполняет доменный CAD-слой.

Сохраняйте каталог состояния между запусками. В нём могут быть локальные пути
документов и данные операций; не публикуйте его в GitHub. Полные ревизии для изменений,
устойчивые ссылки геометрии и блокировка документа после неопределённого изменения
ещё реализуются в рамках первой стадии.

## Общие правила будущих CAD-инструментов

Новые детали и элементы дерева имеют осмысленные русские названия. Стандартные
изделия выбираются из утверждённых Toolbox/корпоративных/PDM-библиотек; исходные
файлы, обозначения стандартов и технические идентификаторы сохраняются. Единицы
контракта: мм, градусы, кг. Документ, конфигурация и выбранный объект указываются явно.
