# Миграция legacy-инструментов в API v2

Снимок dev3. Таблица получена из фактических 92 регистраций `server.py`; каталог v2 содержит 10 других инструментов. Legacy-модуль — источник переноса; рабочая установка v1 сохранена отдельно. Имена ниже в столбце legacy не объявляют доступность соответствующей операции в новом сервере. Переход без устаревших алиасов.

«Изменено / частично» означает доступность только указанной части. «Отложено в v2» означает отсутствие операции в текущем каталоге; номер пункта задаёт место её реализации в согласованном плане, а не отменяет работу. Базовые операции геометрии/документов/измерений должны быть перенесены в 1.4; расширение возможностей — в стадии 2. Ни одна строка с отсутствующей функцией не считается выполненной.

## Новые инструменты без legacy-аналога

`job_get`, `job_list`, `job_cancel`: устойчивое состояние, независимый опрос, отмена очереди. `geometry_get`: восстановление зарегистрированного тела/грани/ребра, проверка native-ссылки и присутствия в активной геометрии. `document_get`: явное чтение заданного документа/конфигурации.

## Непокрытая область

Ревизии изменений, блокировка неопределённого документа, доменный откат, импорт/экспорт и запись существующих параметров ещё требуют native-приёмки стадии 1. Полнота таблицы — это полнота инвентаризации, а не готовность функций. Большие сборки, PDM Professional, сварные конструкции, чертежи, кинематика, сетки/печать и Simulation остаются в полном плане.
