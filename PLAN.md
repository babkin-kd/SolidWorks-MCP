## 1. Цель и принятые требования

Создать MCP для создания с нуля и редактирования смешанных изделий в SolidWorks: деталей, импортированных тел, листового металла, сварных конструкций, чертежей и сборок более 1000 компонентов. Приоритет первого рабочего выпуска — геометрия и изготовление. После них — конфигурации, большие сборки и SOLIDWORKS PDM Professional. Кинематика, подготовка к 3D-печати и Simulation входят в третью стадию. Routing в план не входит.

- Прикладной API v2: явные документы, конфигурации и объекты, типизированные параметры и единый формат результатов. Имена и параметры инструментов могут измениться; устаревшие псевдонимы не входят в v2. Рабочая установка v1 сохраняется на время перехода.
- Отдельная установка для разработки. Проверять совместимость с установленным SolidWorks 2023 SP2.1; поддержку других версий объявлять по результатам проверки.
- **Все создаваемые детали, компоненты и элементы дерева называются на русском языке:** эскизы, операции, вспомогательные плоскости, тела, группы. Примеры: «Кронштейн», «Эскиз основания», «Отверстия крепления», «Скругление кромок». Названия осмысленные и уникальные; при повторении добавляется номер. Технические идентификаторы API не локализуются. Переименование существующих объектов — отдельная операция с проверкой зависимостей.
- **В сборках максимально использовать стандартные элементы из согласованных библиотек:** Toolbox, корпоративная библиотека, каталог PDM. Крепёж, шайбы, подшипники и другие стандартные изделия подбирать по стандарту, размерам, материалу, классу прочности и исполнению. Повторно использовать штатный файл и конфигурацию, не создавать копии одинаковых изделий. Русское имя экземпляра не должно менять исходное имя файла библиотеки, артикул или обозначение стандарта. Если подходящего элемента нет либо найдено несколько вариантов, сообщить об этом; замену или нестандартное изделие оформлять явно.
- Чертежи по ЕСКД/ГОСТ и пользовательским шаблонам: управляемое создание видов и явное размещение размеров и обозначений.
- Развёртки листового металла по пользовательским значениям K-фактора. Отсутствующий профиль нельзя заменять молча произвольным значением.
- Исправление импортированной геометрии — явными операциями с диагностикой и проверкой результата.
- PDM: сначала получение файлов, версии, check-out/check-in. Simulation: сначала статическая прочность сборок с контактами.

## 2. Исходная база и использование upstream

Исходный проект: [hjbaard/SolidWorks-MCP](https://github.com/hjbaard/SolidWorks-MCP). Для планирования зафиксирована версия 0.14.0, commit `a2cb7ad92bb6eacfd9f3d4ce46442bfb9939f340`. Локальная база — `0.13.0+sheetmetal.2`, commit `5485ff9`, tag `baseline/sheetmetal.2`.

В локальной базе зарегистрирован 91 инструмент; в upstream 0.14.0 — 85. Количество регистраций не является оценкой полноты или надёжности. Локальные дополнения листового металла переносить отдельно от изменений upstream. Сохранять текущие изменения `SHEET_METAL_LOCAL.md` и `src/solidworks_mcp/guide.md` и историю исходного проекта; не заменять целиком изменённые общие модули старой копией.

Полезные изменения upstream 0.14.0:

| Изменение | Использование в нашем проекте |
| --- | --- |
| Анализ последствий рекурсивного удаления, dry-run | Основа предварительного просмотра удаления и проверки зависимостей |
| Экспорт STL в системе координат модели | Сохранение положения модели при обмене и подготовке к печати |
| Очистка после неудачного импорта | Доработать обработку COM-исключений и владение временными документами |
| Выдавливание до грани/точки | Перенести с явными ссылками на целевой объект |
| Углы сопряжений со знаком | Проверить диапазоны и фактическое применение при создании и редактировании |
| Перестановка операций в дереве | Перенести с проверкой зависимостей и перестроения |
| Ограниченный повтор записи размера с чтением результата | Использовать как основу проверяемого изменения размеров |

Существующая архитектура Python/FastMCP и одного COM-потока STA полезна. Однако тайм-аут ожидания не останавливает COM-операцию; текущий откат не покрывает все изменения существующей модели; выбор первого тела, непроверенное переименование и успех при ошибке перестроения требуют исправления. Базовый экспорт чертежа не покрывает ЕСКД, сборки и спецификации. Текущий анализ движения и сеток не доказывает непрерывную безопасность механизма или точность произвольной 3D-реконструкции.

Открытые сборки/чертежи и редактирование размеров эскиза пока вне принятого scope. Стадия 1 открыта. Подробности: [базовый сценарий детали](Docs/PART_CREATION.md).

### 1.2. Архитектура API и выбор объектов

- [ ] Разделить слой MCP, доменные операции, COM-привязки, документы/объекты, задания и диагностику.
- [ ] Сохранить один выделенный STA-поток для CAD; корректно создавать и освобождать COM-объекты в его контексте.
- [ ] Каждая операция получает явный `document_id`, конфигурацию и, при необходимости, путь экземпляра компонента. Исключить зависимость от случайного активного документа.
- [ ] Непрозрачные ссылки на тела, грани и рёбра, включая поверхностные тела; persistent references там, где API позволяет. Устаревшая ссылка возвращает понятную ошибку. Индекс объекта не используется как устойчивый идентификатор записи.
- [ ] Единицы контракта: мм, градусы, кг. Явные системы координат, начала и оси эскизов. Импортированная модель не перемещается автоматически в начало координат.
- [ ] Единый ответ: статус, идентификатор операции, контекст, данные, диагностика и ошибка. Успех — после проверки постусловий и отсутствия новых ошибок перестроения. Отличать ранее существовавшие дефекты от новых.

### 1.3. Изменения, тайм-ауты и восстановление

- [ ] Для изменений использовать `request_id` и `expected_revision`; проверять ревизию непосредственно перед исполнением. Ревизия учитывает сессию открытия, конфигурацию, update stamp и собственный счётчик; одного `GetUpdateStamp` недостаточно для всех изменений метаданных.
- [x] Журнал заданий SQLite: `queued`, `running`, `succeeded`, `failed`, `cancelled`, `unknown`. Опрос доступен независимо от занятого CAD-потока.
- [x] Повтор идентичного запроса возвращает прежнее задание; тот же ID с другими аргументами отклоняется. Поздний результат после тайм-аута можно получить без повторного создания операции.

### 1.5. Измерение производительности MCP в опытной эксплуатации

Цель — выявить медленные этапы на реальных инженерных сценариях и выбирать оптимизации по измерениям. Начать с небольшого локального механизма без отдельной инфраструктуры мониторинга; учитывать время работы сервера отдельно от времени разработки, сборок и тестирования.

- [ ] Измерять монотонным таймером полное время вызова и доступные этапы: очередь STA, проверка контекста/объектов/ревизии, COM-операция, явное перестроение, проверка постусловий, восстановление и запись журнала. Вложенные интервалы не суммировать как независимые; перестроение внутри COM-вызова отмечать как неразделимый этап. Тайм-аут ожидания клиента и фактическое завершение задания учитывать отдельно.
- [ ] Записывать инструмент, версию сборки, идентификатор вызова/задания, длительности и исход: успех, известная ошибка, неопределённый результат. Повторное чтение статуса задания учитывать как отдельный запрос, не как повторную CAD-операцию. Не записывать имена изделий, пути, параметры геометрии и содержимое CAD/PDM; идентификаторы использовать только для локальной корреляции.
- [ ] Сделать сбор измерений настраиваемым; ограничить размер/срок хранения локального журнала вне публичного Git. Измерения не вызывают дополнительных обращений к SolidWorks, не создают второй COM-поток и не изменяют семантику заданий. Сбой диагностической записи не маскирует результат операции и не нарушает обязательный журнал заданий.
- [ ] Реализовать один диагностический инструмент, рабочее имя `diagnostics_get_timings`: фильтры по периоду/инструменту, количество вызовов, медиана, p95, самые медленные этапы. Разделять успешные операции и ошибки; показывать размер выборки, не смешивать разные сборки и заведомо разные сценарии. В каталог v2 добавлять только после реализации и проверки.
- [ ] В пробном блоке собрать измерения уже запланированных сценариев создания и редактирования детали; определить основные задержки и выбрать одну обоснованную оптимизацию. Не расширять CAD-прогоны ради объёма статистики и не откладывать основной функционал ради панели мониторинга.

**Проверка результата:** связанные pure-тесты проверяют интервалы, агрегацию, ограничение хранения и отсутствие влияния ошибок диагностики на операции. На точном установленном wheel проверить получение отчёта через MCP и наличие измерений фактической CAD-операции в штатной native-приёмке. Оценить накладные расходы на сопоставимом сценарии с включённым и выключенным сбором; фиксировать условия и объём выборки, не объявлять ускорение по одному прогону. Оптимизации сохраняют полные ревизии, постусловия и восстановление состояния.

## 5. Стадия 3 — дополнительный функционал

Каждый блок выпускается отдельно после собственной приёмки. Наличие CAD-функций не означает доступность лицензируемых модулей.

### 3.1. Кинематика и зазоры

- [ ] Заданная траектория и несколько управляющих параметров; выбор движущейся группы и окружения.
- [ ] Дискретная проверка пересечений и минимальных зазоров с уточнением возле порога; бюджет времени и максимального числа шагов, журнал задания.
- [ ] Явно сообщать полноту обследованной траектории. Дискретная проверка не доказывает отсутствие столкновения между отсчётами.
- [ ] Проверять перестроение на шагах и восстановление размеров, конфигурации и положений в конце.
- [ ] Контрольные механизмы с безопасным движением, известным столкновением и достижением ограничителя. Физическая динамика и силовой Motion-расчёт не входят в первый блок.

### 3.2. 3D-печать, сетки и ограниченная реконструкция

- [ ] Отложенная доработка экспорта STL: диагностика изменения `stl_deviation`, точная проверка восстановления STL-настроек, отдельная native-приёмка. Сохранить прежние отчёты и реализованный код; не переносить их исторический успех на будущие изменения.
- [ ] STL/3MF по выбранным телам и конфигурациям с сохранением системы координат. Для STL требовать единицы; для 3MF учитывать единицы, объекты и build transforms.
- [ ] Проверки замкнутости, manifold, вырожденных элементов, выборочные оценки толщины и нависаний; сравнение сетки с CAD с объявленной методикой и точностью.
- [ ] Первичная реконструкция нативных операций выдавливания/вращения по выбранным сечениям, оси и допуску; сначала проверяемый кандидат, затем явное применение.
- [ ] Произвольное восстановление органической формы и исходной истории построения не обещается.
- [ ] Контрольные модели: обмен с правильными единицами/положением, открытая сетка, модель вращения и выдавливания, проверка ошибки реконструкции.

### 3.3. Simulation: статическая прочность сборок

- [ ] Проверить наличие и лицензию Simulation, версии COM/type library; использовать API, подтверждённый для SolidWorks 2023.
- [ ] Первый сценарий: выбранная сборка/подсборка, объёмная сетка, линейно-упругие изотропные материалы, малые перемещения.
- [ ] Требовать E и коэффициент Пуассона; предел текучести для запаса прочности, плотность при нагрузках от массы.
- [ ] Явные закрепления/заданные перемещения, силы, давления и контакты: bonded и frictionless no-penetration. Не подменять все контакты склеиванием.
- [ ] Управление сеткой и локальными сгущениями; задания построения сетки и решения, чтение напряжений, перемещений, реакций и контактных сил с единицами.
- [ ] Манифест постановки и актуальность результатов. Изменение геометрии/контактов/сетки требует новой сетки; материалов/нагрузок/закреплений — нового решения.
- [ ] Сравнение с вручную подготовленным эталонным расчётом и проверка сходимости сетки. Максимум напряжения в сингулярной точке не использовать как универсальный критерий.

### 3.4. Импорт и экспорт файлов — отложенный функционал

- [ ] Публичный v2 импорт с явными документами, конфигурациями, ревизиями и журналом задания; развитие очистки временных документов для необходимых сценариев. Сохранить ограниченную native-приёмку legacy-импорта dev32 без переноса её результата на другие wheel или неподтверждённые сценарии.
- [ ] Экспорт STEP/Parasolid и других нужных CAD-форматов: сохранение системы координат и единиц, проверка результата и восстановление временно изменённых глобальных настроек.
- [ ] Расширять форматы и набор тестовых моделей по конкретной потребности пользователя. Дефект файлового обмена исправлять раньше только тогда, когда он блокирует выбранный приоритетный инженерный сценарий.
- [ ] Отдельная installed-wheel/native-приёмка каждого выпускаемого блока; STL остаётся в 3.2. Эта работа не является условием завершения стадий 1 и 2, кроме минимального вывода DXF/PDF для принятых производственных сценариев стадии 2.

Native exact-class (`IsTolerant=False`) имеет reported gap `5e-9 м`: он сохраняется точно, с отдельным ограничением `<=5e-9 м`. Независимые проверки точек/линий/плоскостей остаются `1e-12 м`. Превышение пределов, неизвестный тип, ошибки чтения и tolerant-class отклоняются; округления и маскирования геометрии нет. Исходная сессия восстановлена после диагностики. Первая native-проверка аналитического scope dev8 не пройдена; её нельзя считать приёмкой размеров или экспорта.

Для dev9 пройдены **888 локальных тестов**, 321 native-тест исключён. Три агента подготовили исправления и отдельные сценарии внутреннего экспорта и MCP-размеров; агентами выполнены только искусственные/синтаксические проверки. Это приёмка внутренних чтений на собственном блоке, без приёмки записи/отката размера или экспорта. Произвольный BREP и native-полости/разделение граней ещё не приняты.

Native preflight выявил задержку: два полных снимка простого тела заняли 55,86 с, два снимка источника экспорта — 67,859 с. Внутренний `dimension_list/get` вызывает двойную проверку состояния дважды: четыре обхода BREP на одно чтение. До рабочего выпуска убрать вложенные повторения, организовав две полные capture по внешним границам разрешения ссылок, с прежними полями и проверками native identity/конфигурации/событий. Не применять cache по stamp или считать UI lock исключением других COM-клиентов. Без оптимизации этот кандидат нельзя считать готовым по скорости.

Запись размера dev9 **не принята**: первая операция получила `unknown / mutation_rollback_unconfirmed`; приватный журнал `work/native-dimensions-dev9-1/jobs.sqlite` сохраняет `unresolved` application hold и не очищается/не повторяется. Принадлежавшие тесту несохранённые модели закрыты; исходная сессия восстановлена. На отдельной новой диагностической модели `SetSystemValue3` вернул 0 и значение изменилось 7→9 мм, но `EditRebuild3=True` оставил `NeedsRebuild` и физическую глубину 7 мм. После записи 7 мм признак перестроения также остался. Приватный отчёт — `work/dimension-rebuild-diagnostic-dev9-1.report.json`. Поэтому не ослаблять постусловия: проверить принудительное перестроение и его реальные габариты/объём, затем повторить приёмку на новом кандидате/новых тестовых моделях. Наличие такого журнала не объявляет историческое задание согласованным.

Диагностика установила, что новые `Copy/Copy2` неизменного тела дают разные opaque streams при одинаковом body stamp. Канонический геометрический хеш из этих bytes не строится и bytes не маскируются. Подготовлен полный аналитический scope `planar_polyhedral_brep_v1`: native planes, прямые рёбра и trim parameters, вершины, направленные loops/coedges, владельцы и incidence. Сравнение exact без округления, числовой допуск используется только для отклонения несогласованной геометрии. Это первоначальный класс многогранников; произвольный BREP и криволинейная геометрия остаются обязательной доработкой плана. Нужны native-проверка аналитического scope, затем приёмка размера/экспорта. Стадия 1 остаётся открытой.

Локальный кандидат dev7: интегрированы результаты трёх агентов (ревизии, размеры, экспорт). Полный локальный набор — 713 passed, 321 native-тест исключён. Добавлен одноразовый STA UI guard с подтверждением `0 → 2 → 0`; checkpoint уровня приложения записывается до первого `Lock`, проверка ревизии и scoped rollback проходят внутри guard. Освобождение входит в durable доказательства как успешной операции, так и проверенного отказа/отката. Неопределённое освобождение блокирует записи во все документы; повтор запроса не выполняет операцию заново. Guard подключён к публичному переименованию; размеры/экспорт остаются внутренними кандидатами. UI lock не исключает сторонние COM-клиенты и add-in.

Native preflight dev6 выявил некорректный COM-массив конфигураций и ложную проверку наличия design table. Исправлены явный `VARIANT(VT_ARRAY | VT_BSTR)` для чтения/записи и `IModelDocExtension.HasDesignTable()`. Native-владелец `Extrusion` добавлен в проверяемый список.
