# Очистка legacy-импорта: кандидат dev30

Пункт плана 1.4: ошибка импорта не должна оставлять принадлежащие операции временные документы и скрывать исходную причину. Это доработка внутреннего legacy backend; публичный каталог v2 пока содержит прежние 18 инструментов, без document_import.

## Изменение поведения

Общая область импорта включает LoadFile4, проверку типа документа, чтение твёрдых тел и массы детали, чтение компонентов сборки. При любой ошибке Python/COM она возвращает предыдущую ссылку текущего документа и запускает проверяемую очистку. Прежняя очистка срабатывала только при пустом результате или неверном типе; ошибки самого LoadFile4 и последующих чтений оставляли документы открытыми.

Исходные документы идентифицируются каноническим COM IUnknown, удерживаемым до конца операции. Заголовок нужен только для native CloseDoc и проверяется на однозначность непосредственно перед закрытием. Изменение или исчезновение исходного документа, неоднозначное имя, смена данных временного документа и непроверенный результат CloseDoc останавливают очистку. Новые документы закрываются по топологическому порядку зависимостей: внешний родитель перед вложенной сборкой, все родители общей подсборки перед ней, затем оставшиеся новые детали. Повторные экземпляры одного документа дают одно ребро; исходные библиотечные документы исключаются. Цикл или неучтённая зависимость останавливает очистку до закрытия. Native close не повторяется после ошибки или отсутствия наблюдаемого эффекта; сохранение файлов не вызывается.

Происхождение временных документов определяется снимком до/после **одного сериализованного импорта** под флагом CommandInProgress, которым владеет данная сессия. Наличие чужого флага не позволяет заимствовать его для импорта. Это требует отсутствия других процессов, одновременно изменяющих CAD; флаг не является глобальной блокировкой всех COM-клиентов. Такая очистка не используется как фоновое закрытие любых новых документов. Для будущего v2 импорта ещё нужны явные контексты, ревизии, журнал задания и native-приёмка.

3D Interconnect временно отключается только для импорта сборки, если исходно был включён. Возврат настройки проверяется чтением; исключение setter не считается доказательством отсутствия его эффекта. Исходная ошибка сохраняет свой тип/объект, а ошибка восстановления/очистки передаётся дополнительно в diagnostics. При неопределённом результате текущая сессия запрещает следующий импорт до согласования состояния; автоматического повтора нет. Это ограничение импорта не заменяет общую защиту всех legacy-мутаций — пункт 1.3 остаётся открытым.

## Проверка

35 новых pure-сценариев проверяют COM-ошибки загрузки/чтения, ошибки массы и компонентов, поверхностный или неверный тип результата, владение guard, сохранность исходных документов, неоднозначные названия, отсутствие повторного CloseDoc, восстановление настроек и сохранение первичной ошибки. Полный локальный результат: **2081 passed, 323 CAD deselected**. Это искусственные сценарии, без подключений к CAD.

Добавлены восемь native-сценариев для STEP/Parasolid детали и STEP-сборки: успешная загрузка, неверный тип, возвращённая ошибка, инъекция COM-исключения за завершённым LoadFile4 и инъекция ошибки чтения массы. Такие инъекции не доказывают настоящий сбой SolidWorks COM.

Первый установленный dev28 прогон: 2 native теста деталей passed, тест сборки failed до LoadFile4. Ошибка была в Python-проверке результата SetUserPreferenceToggle: зарегистрированный SolidWorks 2023 typelib возвращает VT_VOID (24), а не Boolean. Код ошибочно воспринимал None как отказ, включая восстановление настройки. Независимые после-прогона чтения подтвердили исходные настройки, 3D Interconnect, видимость, пустую сессию и снятый guard; исходный failed-отчёт сохранён, общей native-приёмки нет. Пользователь согласовал сброс прежнего флага и новый baseline; после failed-прогона baseline подтвердился точно, дополнительного сброса не выполнялось.

Dev29 исправляет этот дефект: результат void не используется как ACK, после setter всегда читается фактический toggle. Fake API теперь соответствует void-сигнатуре; отдельный сценарий проверяет void-setter без наблюдаемого эффекта. Официальная [сигнатура ISldWorks.SetUserPreferenceToggle](https://help.solidworks.com/2021/English/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.ISldWorks~SetUserPreferenceToggle.html) также объявляет void; сигнатура установленного swconst/sldworks 31 проверена непосредственно локально.

Свежий установленный dev29 (`63234a7`) прошёл **6 native-тестов**: STEP/Parasolid детали, STEP-сборка с сохранением положения компонентов, отказ part-as-assembly, очистка после error-result и после Python-инъекции COM-исключения за реальным LoadFile4. Native-прогон остановился на отказе assembly-as-part; тест последующей ошибки массы не запускался. **Общая приёмка false**. В сессии осталось четыре новых контрольных документа; flag снят, видимость, 3D Interconnect и все 11 проверяемых non-STL-настроек восстановлены. Из восьми отложенных STL-полей изменился только stl_deviation — его успех не заявляется.

Пассивный native-снимок показал внешнюю сборку `pair`, её вложенную `pair.step.SLDASM` и две детали. Простая группировка «все сборки первыми» ставит вложенную сборку раньше её родителя; такая сборка удерживается родителем. Это воспроизведено отдельным pure-сценарием. Dev30 строит DAG по каноническим идентичностям GetModelDoc2 и закрывает родителей перед детьми; проверяет общий дочерний документ, дубликаты экземпляров, библиотечные документы, циклы и неучтённые зависимости. В native-тестах теперь явно проверяются notes ошибки очистки, чтобы отказ не скрывался за последующим сравнением количества документов.

**Native-приёмка исправленного dev30 ещё не выполнена**. Контрольные документы сохранены открытыми до согласования закрытия по AGENTS.md; старый failed-прогон не повторяется и не объявляется успехом. Реальные поверхности без твёрдых тел, сложные импортированные модели и полный v2 импорт/явные контексты остаются в плане.

Рабочая v1 не заменяется. STL остаётся отложенным, этап 1 не завершён.
