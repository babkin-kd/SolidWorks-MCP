# SolidWorks MCP — контракт v2 в разработке

Это отдельная точка входа `solidworks-mcp-v2 --state-dir <постоянный локальный каталог>`.
Рабочая установка v1 остаётся отдельно. В этом кандидате реализованы журнал заданий
и явное чтение метаданных документов/геометрии/элементов деталей, проверяемое
переименование элемента, изменение поддерживаемого размера и экспорт детали;
остальные операции моделирования ещё переносятся.
Полный план развития находится в `PLAN.md`. Стадия 1 закрывает базовые операции и безопасность; новые инженерные операции
расширяются в стадии 2 после её приёмки, как указано в плане.

## Доступные инструменты

| Инструмент | Результат |
| --- | --- |
| `system_get_info` | Версии API/пакета/схемы/SDK, hash каталога инструментов, данные сборки и фактические возможности |
| `job_get` | Состояние и данные задания по `operation_id`, включая поздний результат |
| `job_list` | Постраничный список заданий; оба поля курсора передаются вместе |
| `job_cancel` | Атомарная отмена задания в очереди; исполняемое задание не отменяется |
| `diagnostics_get_timings` | Локальные count/median/p95 по периоду и операции; сборки/исходы/jobs/MCP/polls отдельно. Сбор включается оператором, по умолчанию выключен; CAD не вызывается |
| `document_list` | Открытые документы: непрозрачные ID, конфигурации, метаданные, токены наблюдаемого состояния |
| `document_get` | Метаданные явного документа и существующей конфигурации без их активации |
| `document_list_templates` | Настроенный `.prtdot`, fingerprint, непрозрачный `template_id` и application ID текущего соединения |
| `document_prepare_create_part` | Read-only подготовка русских имён и новой application-ревизии по шаблону, открытым деталям и видам |
| `document_create_part` | Создание/активация новой пустой несохранённой детали; scoped closure только собственного результата при известном сбое |
| `body_list` | Страница твёрдых/поверхностных тел явной детали; непрозрачные `object_id` |
| `face_list` | Страница граней заданного `body_id`, площадь в мм² и тип поверхности |
| `edge_list` | Страница рёбер заданного `body_id`, длина и концы в мм |
| `geometry_get` | Восстановление тела/грани/ребра по зарегистрированному `object_id` |
| `feature_list` | Страница полного дерева элементов детали с persistent ID и ревизией области `part_feature_tree_v1` |
| `feature_get` | Восстановление элемента по opaque ID, актуальное имя/тип/состояние и ревизия дерева |
| `feature_rename` | Русское имя заданного элемента с ревизией, checkpoint, проверкой результата и восстановлением имени при ошибке |
| `dimension_list` | Страница размеров детали со значениями в мм/градусах, устойчивыми ссылками, ограничениями записи и ревизией `part_dimension_values_v1` |
| `dimension_get` | Чтение явно указанного размера с проверкой native identity и принадлежности владельцу |
| `dimension_set_value` | Изменение независимого размера элемента с проверкой ревизии, rebuild, readback и подтверждённым восстановлением при ошибке |
| `part_prepare_base_extrusion` | Подготовка прямоугольного основания пустой детали: явная плоскость, русские имена, размеры в мм и полная ревизия |
| `part_create_base_extrusion` | Параметрический эскиз и выдавливание по подготовленной ревизии, с проверкой BREP и откатом только собственных объектов |
| `sketch_get` | Полное чтение поддерживаемого линейного плоского эскиза, всех связей и их определяющих сущностей |
| `sketch_prepare_dimension_change` | Подготовка изменения ширины/высоты полностью определённой прямоугольной базы |
| `sketch_set_dimension` | Изменение подготовленного размера с перестроением и проверкой полной формы/объёма/площади |
| `export_prepare` | Read-only проверка явной детали и параметров экспорта; возвращает ревизию `part_solid_brep_export_v1` |
| `export_part` | STL/STEP/Parasolid без перезаписи файла, с проверкой исходной модели, настроек и манифестом результата |

Опрос журнала не требует доступа к SolidWorks и не ждёт занятого STA-потока.

Схема журнала 3 сохраняет внутренние checkpoint изменений и блокировки неопределённого
состояния. Если у задания есть checkpoint, `job_get`/`job_list` добавляют поле `mutation`:
цель, состояние до записи, фазу и свидетельство проверки/согласования. После аварии
неподтверждённое изменение не повторяется. Переподключение не снимает блокировку.
Схема 3 сохраняет доверенную область побочных эффектов. Неопределённые изменения
общих настроек приложения блокируют записи во все документы; переход из схем 1/2
сохраняет задания. Старый runtime схемы 2 не должен открывать этот новый журнал.
Протокол подключён к `feature_rename`, `dimension_set_value`, `export_part`, `part_create_base_extrusion` и `document_create_part`.
Диагностика указывает `cad_mutations=true` и точный список
`implemented_mutations=["feature.rename", "dimension.set_value", "export.execute", "part.create_base_extrusion", "document.create_part"]`.
Клиентская команда снятия блокировки ещё не предоставляется.
Создание документа поддерживает только настроенный существующий `.prtdot`, пустую
сессию или открытые детали без редактируемого эскиза и пустой шаблон с одной
конфигурацией. Русские заголовок/конфигурация задаются без сохранения файла.
`application_id` из подготовки служит явной целью, durable context содержит его
как `document_id` при `configuration=""`; настоящий новый `doc_*` возвращается
в `data.after.created_document_id`. Исходные детали не закрываются/не сохраняются,
их выделения/метки защищены. Неизвестный `NewDocument` не повторяется.
Инструмент выполнения произвольного кода или произвольного имени CAD-метода не предоставляется.
Чтение документа — задание на единственном STA-потоке. Его `request_id` обязателен;
новый снимок требует нового ID. Повтор возвращает исторический результат прежнего
задания, даже если модель уже изменилась. `timeout_s` от 0 до 120 задаёт только время
ожидания; при `queued`/`running` опрашивайте `job_get` по возвращённому `operation_id`.
Данные завершённого чтения находятся в `data`, а при опросе `job_get` — в `data.result`.

Сначала вызовите `document_list`, затем передайте полученные `document_id` и точное
имя конфигурации в `document_get`. Пустое имя допустимо лишь для документа без
конфигураций. Нет автоматического выбора активного документа или первого тела.
Чтение не переключает конфигурации, не перестраивает и не сохраняет документы,
не меняет видимость SolidWorks и не раскрывает lightweight-компоненты сборки.
ID относятся к текущему соединению: после перезапуска сервера список нужно получить
заново. Исторические ID в завершённых заданиях не становятся актуальными от их чтения.

`observation_revision` покрывает только update stamp и метаданные документа:
заголовок, путь, конфигурации, флаг сохранения и наблюдаемый счётчик изменений.
Неизменный токен не доказывает неизменность всех свойств, операций или материалов;
изменение и возврат между наблюдениями могут остаться незамеченными. Это ещё
не `expected_revision` для мутаций. Чтение геометрии неактивной конфигурации ещё
не предоставляется; для геометрических изменений эта ревизия не используется. Переименование элемента
требует отдельной ревизии дерева из `feature_list`/`feature_get`.

## Дерево элементов и переименование

Только детали и явная активная конфигурация, без активации/перестроения/сохранения.
Дерево включает поглощённые подэлементы. Ревизия `part_feature_tree_v1` учитывает
ID открытия/соединения и конкретной конфигурации, document update stamp и метаданные,
полное дерево имён/типов/владельцев/подавления/ошибок, счётчик native-уведомлений и
собственный счётчик попыток записи. Дерево ограничено 5000 элементами; при превышении
выдаётся ошибка, неполной ревизии нет. Страницы 1–200 элементов привязаны к ревизии.
Native `GetID` нужен только для обхода/сопоставления диагностики, не для восстановления
клиентского объекта. `object_id` восстанавливается через persistent reference и проверяется
на присутствие в текущем дереве. Узлы без корректной native persistent reference имеют
`object_id=null` и `reference_error`; неверная ссылка не заменяется поиском по имени или ID.

Это объявленная область ревизии для переименования, не обещание охвата произвольных
данных сторонних модулей, всех визуальных свойств или внешних файлов. `ModifyNotify`
сообщает первое загрязнение документа и не заменяет снимок/другие уведомления. Новые
операции обязаны расширить свою область защиты. COM-поток обрабатывает сообщения;
native-обработчики только увеличивают счётчик, без reentrant CAD-вызовов.

Повторная проверка и setter — отдельные native-вызовы внутри одноразового UI guard.
После durable checkpoint уровня приложения native `Lock` должен подтвердить
состояние 2, после операции/проверенного отката `UnLock` — состояние 0. В журнале
сохраняются наблюдения `execution_guard`; неопределённое освобождение запрещает
последующие записи во все документы. UI lock блокирует интерактивное редактирование;
общая блокировка сторонних COM-клиентов/add-ins не гарантируется. Счётчик событий
не доказывает атомарность.

Перед `feature_rename` получите свежие `object_id`/`revision`; передайте их как
`object_id`/`expected_revision`, а также `request_id`, документ, конфигурацию и русское
`name`. Проверка выполнится ещё раз на STA после checkpoint и перед первой записью.
Чужая/удалённая ссылка, другая конфигурация, устаревшая ревизия, необходимость
перестроения, подавленная цель, занятое/недопустимое имя отклоняются. Имя читается после
записи; остальное дерево/ошибки/stamp должны совпасть с ожидаемой областью. Ранее
существовавшие ошибки не объявляются новыми. При ошибке восстанавливается конкретное
имя; чужое новое имя не перезаписывается. Неподтверждённое восстановление сохраняет
блокировку, а чтение/опрос доступны. Это не полный Undo документа или восстановление
его флага сохранения. После `timeout_s=0` опрашивайте `job_get`; повтор того же запроса
не делает вторую запись и возвращает историческое задание.

## Чтение геометрии

Для геометрии передайте явные `document_id`, активную `configuration` и текущий
`expected_observation_revision` из `document_get`/`document_list`. Это проверка
согласованности чтения, **не полный expected_revision для будущих мутаций**.
Неактивная конфигурация, другая ревизия наблюдения и необходимость перестроения
отклоняются до перечисления геометрии. Только детали; геометрия экземпляров сборок,
координаты компонента и чтение неактивной конфигурации ещё не приняты.

`body_list` принимает `body_type=all|solid|surface` и включает скрытые native-тела.
`all` означает твёрдые и поверхностные тела, не сеточные/графические/проволочные.
Полученный `object_id` тела передаётся как `body_id` в `face_list`/`edge_list`.
Геометрические ID принадлежат документу и конкретному объекту конфигурации. Они
восстанавливаются через native persistent references и проверяются на принадлежность
родительскому телу. Удалённая, подавленная, чужая или неверная ссылка не заменяется
первым телом/индексом. Проверяется фактическое присутствие тела и топологии в
активной конфигурации: native status=OK сам по себе этого не доказывает.
Пересоздание одноимённой конфигурации не восстанавливает её
старые ссылки. После закрытия документа/перезапуска MCP нужны новые ID.

Native persistent ID не передаётся клиенту. Сериализация ID может измениться после
перестроения; сравнение выполняется через API SolidWorks. Для того же native-объекта
возможно несколько непрозрачных ID; каждый остаётся связан с исходной ссылкой.
Переименование не используется для поиска объекта. Без native persistent reference
операция возвращает ошибку, а не менее надёжный индекс.

Списки принимают `limit=1..200`, возвращают `items`, `total_count`, `next_cursor`.
Следующая страница требует нового `request_id`, того же контекста и курсора.
Курсор привязан к исходному перечислению, запросу и ревизии; его нельзя переносить
между телами/типами объектов или использовать после изменения документа. Размер
ответа ограничен страницей; native API всё ещё перечисляет полную коллекцию.
Бюджеты на документ: 100000 объектов в коллекции/снимках страниц, 100000 ссылок,
10000 курсоров; превышение — явная ошибка. Снимки удерживаются только в STA и не
попадают в SQLite. Они освобождаются при закрытии документа, обнаружении новой
ревизии или серверном shutdown; старые ссылки не переигрываются автоматически.

Все координаты остаются в системе модели, длины — мм, площади — мм². Bounding box
тела помечен `approximate=true`: он не является точным метрологическим измерением.
Поверхностное тело не получает выдуманного объёма или массы.

## Размеры

Начните с `dimension_list` или `dimension_get`: они возвращают отдельную ревизию
`part_dimension_values_v1`, значения, единицы и причины запрета записи. Ревизия дерева
или наблюдаемого состояния не разрешает изменение размера. Ссылки проверяются по
native identity, persistent reference и присутствию у владельца; имена и порядковые
номера не заменяют устойчивую ссылку. Область ревизии включает полную поддерживаемую
аналитическую геометрию плоских многогранников; неподдерживаемая геометрия отклоняется.

`dimension_set_value` требует активную деталь с одной конфигурацией, независимый
размер элемента, `object_id`, `expected_revision`, `request_id`, `value` и `unit`.
Линейное значение — конечное положительное число в мм; угол — от 0 до 360 градусов
без включения границ. Единицы должны совпасть с типом размера. Размеры эскизов
этим инструментом не изменяются. Для ширины/высоты прямоугольной базы служит
отдельный контракт `sketch_prepare_dimension_change` / `sketch_set_dimension`.
Driven, связанные, справочные, управляемые таблицей
размеры и неподдерживаемые зависимости/уравнения явно отклоняются.

После checkpoint инструмент повторно проверяет состояние, записывает значение,
перестраивает целевой документ и проверяет фактическое значение, геометрию и ошибки
элементов. Он не активирует и не сохраняет модель. При ошибке восстанавливается
принадлежащее операции значение; успех восстановления требует отдельной проверки.
Повтор `request_id` не выполняет запись ещё раз. При `unknown` нужно согласование
состояния, автоматический повтор с новым ID запрещён.

## Эскиз прямоугольной базы

`sketch_get` получает object_id из `feature_list` и полностью читает поддерживаемый
линейный плоский эскиз: точки, линии, определённость, все внутренние и определяющие
сущности связей, native Type2 размеров, начало модели, плоскость и преобразования.
Ревизия `part_linear_sketch_read_v1` содержит точные hex координаты в СИ. Локальные
ID точек/линий остаются сведениями для чтения. Дуги/сплайны, 3D, внешняя геометрия,
блоки/слоты/изображения/текст/штриховки пока вызывают отказ, а не частичный результат.

Для записи отдельно вызовите `sketch_prepare_dimension_change` с явными документом,
конфигурацией, object_id эскиза, собственным dimension_id из `dimension_list` и новым
value_mm. Scope ограничен активной одноконфигурационной деталью: полностью определённый
прямоугольник, угол на настоящем начале модели, четыре линии, семь определяющих связей,
два независимых размера и одно положительное blind base extrusion. Оси определяются по
native ориентации размеров, а не именам. Диапазон: 0,001–10 000 000 мм.

`sketch_set_dimension` принимает те же параметры и expected_revision scope
`part_rectangular_sketch_dimension_v1`. Ревизия связывает конкретный новый размер со
всем поддерживаемым состоянием; ревизия чтения эскиза не заменяет ревизию подготовки.
После checkpoint выполняются одна запись и перестроение, проверяются все прочие
размеры/связи/метаданные, полный BREP и native объём/площадь. Scoped restoration
подтверждает полную исходную прямоугольную форму с явными допусками округления решателя:
10⁻¹² м для точек, 10⁻⁹ м для вершин BREP, 10⁻¹⁰ относительный и 10⁻⁸ абсолютный для
native объёма/площади в мм³/мм². Другие изменения блокируют восстановление; unknown
не повторяется. Выделение и UI lock сохраняются, модель не активируется и не сохраняется.

## Экспорт детали

Оператор задаёт существующий каталог при запуске:
`solidworks-mcp-v2 --state-dir <журнал> --output-dir <каталог экспорта>`.
`system_get_info.export_output_configured` сообщает наличие этой настройки, без
проверки файловой системы или соединения с CAD. Без настройки оба инструмента
отказывают с `export_output_not_configured` до создания задания или CAD-потока.
Клиент передаёт только простое `filename`; каталог, перезапись и произвольный путь
не являются аргументами инструмента.

`export_prepare` принимает `document_id`, активную `configuration`, `file_format`,
`filename`, `units` и `request_id`. Поддержаны `stl`/`.stl`, `step`/`.step`,
`parasolid`/`.x_t`. Только твёрдые детали в поддерживаемой области плоского
аналитического BREP; сеточные, криволинейные, смешанные и неоднозначные тела
отклоняются. Источник не активируется, не перестраивается и не сохраняется.

Для STL обязательны явные `units=mm|m|in`; единицы отсутствуют в самом файле.
Система координат модели и отрицательные координаты сохраняются, текущая точность
триангуляции сохраняется. Для STEP/Parasolid передайте `units=""`. STEP проверяет
согласованные SI length contexts во всём файле до 4 МиБ; единицы Parasolid не
объявляются проверенными без независимого геометрического roundtrip.

Передайте полученную ревизию как `expected_revision` в `export_part` с теми же
параметрами. Инструмент сохраняет checkpoint, проверяет исходную геометрию и настройки,
восстанавливает собственные временные настройки и публикует один файл без перезаписи.
Манифест содержит размер, SHA-256, систему координат, свидетельства единиц и
`staging_cleanup`. Статус `retained_empty_directory` явно сообщает о собственном
пустом временном каталоге, оставленном после подтверждённой публикации из-за Windows
error 32; его identity и отсутствие файлов проверяются. Другие ошибки не маскируются.
Манифест не подтверждает обратный импорт или полное геометрическое равенство STEP/
Parasolid. Тайм-аут не отменяет COM; результат получают через `job_get`.

## Ответы и задания

Числовые аргументы передавайте числами JSON: строки и `true`/`false` не заменяют
тайм-аут, лимит, значение размера или числовой курсор. Неверный тип отклоняется
при проверке MCP-запроса до запуска CAD; это ошибка аргументов протокола.

Ответ содержит `status`, `operation_id`, `context`, `data`, `diagnostics`, `error`.
Для `job_get` статус относится к самому заданию; для списка/отмены — к запросу
наблюдения, а состояние задания находится в `data`. Отказ отменить уже исполняемое
задание виден как `data.cancelled=false`; это не остановка COM-операции.

Состояния: `queued`, `running`, `succeeded`, `failed`, `cancelled`, `unknown`.
`request_id` однозначно связан с операцией, аргументами и контекстом. Повтор
идентичного запроса возвращает прежний результат, тот же ID с другими аргументами
отклоняется. Истечение времени ожидания и отмена ожидания не отменяют само задание.
Мутация требует проверки постусловий. Непроверенный результат или неожиданная
ошибка после возможного изменения получают `unknown`, а не ложное подтверждение успеха.

SQLite-журнал использует атомарные переходы состояний и эксклюзивное владение
на уровне ОС. Второй процесс не может сбросить задания живого владельца. После
аварийного завершения `queued`/`running` становятся `unknown`, завершённые результаты
сохраняются. Никакие записанные операции автоматически не повторяются.
`failed` после изменения допустим только при подтверждённом неизменном состоянии
или проверенном откате; проверку и восстановление выполняет доменный CAD-слой.

Сохраняйте каталог состояния между запусками. В нём могут быть локальные пути
документов и данные операций; не публикуйте его в GitHub. Полные ревизии для изменений,
устойчивые ссылки геометрии и блокировка документа после неопределённого изменения
ещё реализуются в рамках первой стадии.

## Сквозной угловой вырез

В кандидат dev51 добавлены `part_prepare_corner_cut` и `part_create_corner_cut`.
Подготовка связывает явные документ, конфигурацию, opaque ID эскиза основания и его
точной плоскости, размеры выреза в мм и русские имена. Начальный сценарий — пластина
с одной прямоугольной базой: угол 10 × 5 мм насквозь в пластине 40 × 20 × 10 мм оставляет
L-образное тело объёмом 7500 мм³. По обеим осям остаётся минимум 0,001 мм материала.
Запись требует полученной ревизии и request_id, сохраняет исходные размеры/ограничения,
проверяет полный BREP и native объём/площадь. При известном сбое удаляются только точные
собственные эскиз/вырез; чужие зависимости и изменения блокируют восстановление.
Тайм-аут не отменяет COM. Импорт/экспорт отложены; произвольные карманы и отверстия
в этот начальный scope не входят. Изменение размеров базы после добавления выреза
требует следующего расширения контракта. Native-приёмка относится к точному wheel
и документируется отдельно; наличие команды в dev-кандидате не заменяет её.

## Общие правила будущих CAD-инструментов

Новые детали и элементы дерева имеют осмысленные русские названия. Стандартные
изделия выбираются из утверждённых Toolbox/корпоративных/PDM-библиотек; исходные
файлы, обозначения стандартов и технические идентификаторы сохраняются. Единицы
контракта: мм, градусы, кг. Документ, конфигурация и выбранный объект указываются явно.
# Полный оборот основания: кандидат dev52

`part_prepare_base_revolve` и `part_create_base_revolve` реализуют ограниченный
сценарий `empty_part_full_turn_cylinder_revolve_v1`: активная пустая деталь,
одна конфигурация, явный `plane_object_id` плоскости в начале координат,
`radius_mm`, `height_mm`, `axis="profile_y"`. Ось — собственная линия x=0
созданного прямоугольного профиля. Имена по умолчанию: «Эскиз вращения»,
«Вращение основания», «Тело вращения»; управляющие размеры — «Радиус»,
«Высота вращения», «Угол вращения» (360°).

Подготовка читает полное состояние и возвращает ревизию; создание требует
тех же параметров, документа/конфигурации, ревизии и `request_id`. Проверяются
полная сеть ограничений профиля, две окружности с замкнутыми native trim,
два плоских торца, цилиндрическая поверхность и все loop/coedge-связи,
независимые native объём/площадь и сохранность исходного контекста.
Первый сценарий не редактирует существующие вращения и не создаёт сектор,
конус, полый цилиндр или произвольный профиль. Общая запись угла 360° через
`dimension_set_value` остаётся запрещена; радиус/высота этого профиля не входят
в принятый контракт изменения прямоугольной выдавленной базы.

BREP ревизии сохраняет прежний `planar_polyhedral_brep_v1` для полностью
плоского набора тел. При наличии полного цилиндра используется
`planar_cylinder_or_single_hole_body_set_v1`, у каждого тела свой полный `scope`.
Цилиндр с seam, дополнительными разбиениями или иной криволинейной
геометрией отклоняется до отдельной реализации полного reader.
Статус кандидата и installed/native-приёмки фиксируется в документации
проекта; метаданные разработки сами по себе не подтверждают CAD-приёмку.

## Сквозное круглое отверстие — кандидат dev55

`part_prepare_through_hole` читает явные документ/конфигурацию, исходный
прямоугольный эскиз (`object_id`) и его точную плоскость (`plane_object_id`).
Центр X/Y и диаметр задаются в мм в системе исходной плоскости; каждая длина
не меньше 0,001 мм. До всех четырёх сторон основания должно оставаться
минимум 0,001 мм материала. Поддерживается одна положительная blind-база
без последующих операций; чужие/импортированные модели требуют расширения
полного контракта. Подготовка возвращает собственную ревизию
`single_base_circular_through_hole_v1`.

`part_create_through_hole` требует те же цели/параметры, ревизию и request_id.
Создаёт «Эскиз отверстия» и «Сквозное отверстие» с независимыми размерами
«Центр X», «Центр Y», «Диаметр». До записи — durable checkpoint/STA guard;
после — полные исходные ограничения/размеры, circle relations/definitions,
полная граница 8 вершин/14 рёбер/7 граней, rebuild и независимые V/A.
Сохраняются выделение/marks и имя исходного тела. Известная ошибка допускает
удаление только доказанных собственных cut/sketch; foreign/unknown удерживают
приложение и не повторяются автоматически. Тайм-аут ожидания не отменяет COM.
Повтор request_id возвращает существующее задание.

Это кандидат реализации. Installed/native-приёмка отверстия фиксируется
отдельно; наличие инструмента в исходном каталоге не доказывает её прохождение.
Blind/наклонные отверстия, зенковки, резьбы, Hole Wizard и редактирование базы
после отверстия не входят в эту начальную область.

## Размеры существующего отверстия — кандидат dev56

`part_prepare_hole_dimension_change` получает явные документ/конфигурацию,
`base_object_id` прямоугольного исходного эскиза, `object_id` круглого эскиза,
`dimension_id` из `dimension_list` и новое `value_mm`. Поддерживает только
независимые размеры центра X/Y и диаметра единственного сквозного отверстия.
Подготовка читает полные ограничения, размеры, основание и тело, проверяет запас
материала не менее 0,001 мм со всех сторон. Ревизия
`single_base_circular_through_hole_dimension_v1` привязана также к новому значению.

`part_set_hole_dimension` требует те же цели и значение, подготовленную ревизию
и request_id. Проверяет перестроение, неизменность основания/других размеров,
полную BREP-форму, независимые объём/площадь, имя тела и служебные настройки.
Подтверждённая собственная ошибка восстанавливает только исходное значение
целевого размера. Чужие или нечитаемые эффекты блокируют приложение; повторная
запись не выполняется. Повторный request_id возвращает прежнее задание.
Импортированные тела, несколько отверстий и изменение толщины основания после
отверстия в эту область не входят. Native-приёмка кандидата учитывается отдельно.

## Защита model-мутаций — dev55

После durable application-wide checkpoint model-мутация получает собственный CommandInProgress, блокировку явного документа и selection scope. Исходный флаг обязан быть False; существующий True возвращает application_busy и не сбрасывается. Освобождение собственного флага проверяется чтением; неподтверждённое освобождение оставляет unknown и application-wide hold. Подготовительные чтения пока не переключают флаг. Тайм-аут ожидания не отменяет COM. Это изменение общего исполнения, новые CAD-инструменты не добавлены; native-приёмка фиксируется отдельно на точном wheel.


## Линейный массив сквозных отверстий — кандидат dev58

`part_prepare_linear_hole_pattern` и `part_create_linear_hole_pattern` создают
один native LPattern существующего сквозного отверстия в прямоугольной базе.
Явно передавать документ, конфигурацию, `base_object_id` эскиза базы, `object_id`
окружности, `seed_object_id` её выреза из `feature_list` и `direction_edge_id`
из `edge_list` текущего тела. Полное прямое внешнее ребро задаёт положительный
локальный X или Y базы; ребро вдоль толщины не подходит. Количество 2–64 включает
исходное отверстие, шаг задан в мм, зазор между отверстиями и до края >=0,001 мм.
Имя нового элемента по умолчанию «Линейный массив отверстий».

Подготовленная `single_base_linear_through_hole_pattern_v1` ревизия связывает
все цели, исходные размеры/ограничения/BREP, направление, количество и шаг.
Запись требует ту же ревизию и input, checkpoint и request_id. Проверяются
native seed/axis/параметры, неизменность обоих исходных эскизов, полный BREP
всех отверстий и независимые объём/площадь. Известный подтверждённый сбой
удаляет только собственный массив; исходный вырез и эскизы сохраняются.
Неопределённый исход удерживает приложение; тайм-аут не отменяет COM.
Двухнаправленные/круговые массивы, пропуск экземпляров, произвольные тела и
редактирование базы/отверстия после массива пока вне этого scope.
Native-приёмка dev58 описывается отдельным отчётом; возможности v1 не наследуются.

## Скругление явно выбранного ребра

`part_prepare_edge_fillet` / `part_create_edge_fillet`: явный эскиз основания,
ребро текущего тела, радиус в мм, русское имя и ревизия подготовки. Первый

## Листовой профиль с одним сгибом

`sheet_prepare_l_profile` / `sheet_create_l_profile`: пустая активная деталь,
одна конфигурация, явная persistent-плоскость в начале координат. Профиль
(0,H) → (0,0) → (W,0), толщина влево, длина вдоль положительной нормали,
внутренний радиус и **обязательный явный K-фактор**; размеры в мм.
Ревизия `empty_part_sheet_l_profile_v1` связывает полный empty-state,
плоскость, параметры и ожидаемый folded-BREP со швами сгиба.

Native body/sketch/allowance/ownership и три driving-размера проверяются
после создания. Все новые узлы и размер длины получают русские имена.
Известный сбой позволяет удалить только полностью доказанный собственный
bundle; чужие узлы/зависимости запрещают восстановление. Unknown сохраняется
и не допускает повторной записи; время ожидания не отменяет COM.
Это folded-основание с одним сгибом90°, без arbitrary profiles, редактирования
существующих отбортовок, native-развёртки или DXF. Нейтральная длина в
подготовке — аналитический прогноз. Native-приёмка кандидата требует
отдельного отчёта точного установленного wheel и MCP-вызова.


## Existing native L-sheet flat/folded state

Use `sheet_prepare_flat_state` with explicit document/configuration/base_object_id
and a required boolean flattened. The native K-factor is read and bound to the
revision; it is not overridden. The exact flat pattern is derived from the
strong base and complete body/folder membership. One active independent
configuration and the supported original two-line L-profile are required.

Pass the same parameters/revision to `sheet_set_flat_state`. The guarded operation
re-proves fresh bodies and the full intended material BREP before preserving
original body/cut-list names if SolidWorks auto-renames them. Original drivers,
K/parameters, controls and every other node are preserved. Known failure may
restore only the proved original state/names, with full verification; no delete
or generic Undo. Same request_id never starts another change; timeout only limits
waiting, not COM execution. Unknown cannot be auto-repeated. No new configuration,
save, export/DXF or arbitrary sheet geometry is implemented by these tools.


### Параметры существующего листового L-профиля

`sheet_prepare_parameters` читает текущие параметры и готовит явное изменение
толщины, радиуса и K-фактора по одному document/configuration/base_object_id.
Все три значения обязательны; размеры полок, длина и flat/fold состояние сохраняются.
`sheet_set_parameters` требует полученную ревизию и request_id. Изменение относится
к одному самостоятельному L-профилю/телу/конфигурации с native-сгибом90°,
согласованными template/body defaults и отключённой gauge-table. Материал/таблицы,
дополнительные сгибы и конфигурации требуют других инженерных сценариев.

Проверяются полный BREP, независимые native t/r/K, исходная сеть размеров,
настройки разгрузки и неподвижная полка/сторона. Исходные русские имена тела/списка
сохраняются после доказанного изменения. Неопределённый native-результат не повторять;
тайм-аут не отменяет COM, используйте job_get. Файловый обмен в этот сценарий не входит.

## Отбортовка существующего листового L-профиля

`sheet_prepare_edge_flange` принимает явные документ, конфигурацию, основание
и полное продольное ребро внутренней свободной грани вертикальной полки.
Первый scope ограничен согнутым L-профилем с одной независимой конфигурацией,
одним телом и горизонтальной фиксированной полкой. Наружная длина отбортовки,
радиус и пользовательский K-фактор второго сгиба обязательны. Подготовка
возвращает ревизию и полную ожидаемую U-геометрию без записи в модель.

`sheet_create_edge_flange` требует эту ревизию и request_id. Создаются штатная
отбортовка на 90 градусов внутрь, полностью определённый профиль и дочерние
сгибы с русскими именами. Сохраняются исходные размеры, первый сгиб, K-фактор,
имена тела и исходных элементов. Проверяется весь BREP и native-параметры.
Восстановление удаляет только полностью доказанную собственную отбортовку
или завершённый собственный входной эскиз. Чужое или промежуточное состояние
остаётся unknown. Тайм-аут ожидания не отменяет COM: проверяйте job_get.
Развёртка нового U-профиля и произвольные листовые детали требуют отдельного
расширения и native-приёмки.


## Кандидат состояния U-профиля с двумя сгибами

`sheet_prepare_flange_flat_state` готовит read-only ревизию для явных основания
и отбортовки одной существующей листовой детали/конфигурации.
`sheet_set_flange_flat_state` переключает её FlatPattern и проверяет всю
физическую границу U/развёртки. Оба native-радиуса и пользовательских K,
эскизы, шесть размеров, fixed-face membership и имена сохраняются.
Первый scope: исходная горизонтальная фиксированная полка и U-профиль из
поддержанного L-профиля с одной внутренней отбортовкой90°.

Обязательны document_id, configuration, base_object_id и flange_object_id;
flattened — строгий boolean. Запись требует expected_revision и request_id.
Тайм-аут ограничивает ожидание, а не COM; terminal-результат читается job_get.
Только полный доказанный переход разрешает возврат прежнего состояния.

`--timings-retention-days`, `--timings-max-mib`. Хранилище `timings.sqlite`
приватное и отдельное от обязательного журнала заданий. Аргументы, пути, имена
моделей и текст ошибок не записываются. Вложенные этапы inclusive нельзя
складывать; COM coverage охватывает только явно измеренные вызовы. Сценарий
пока `unclassified_v1`, завершённые job traces и время MCP-ожидания учитываются
отдельно. Тайм-аут и отмена ожидания не отменяют исполняемую CAD-операцию.
# Измерение массы детали

`measurement_prepare_mass` читает явный document_id/активную configuration и
expected_observation_revision. body_id=None означает все solid-тела, включая
скрытые; поверхности исключены. Явный body_id измеряет только это solid-тело.
Возвращаемая revision имеет scope part_mass_selection_measurement_v1: состав
тел, геометрические моменты и исходное выделение. Это ревизия измерения.

`measurement_get_mass` требует эту expected_revision и request_id. Геометрия
не редактируется, но временное выделение/блокировка/CommandInProgress защищены
durable application checkpoint. Исходные объекты и marks восстанавливаются
ровно один раз. Результат: мм³/мм²/кг/кг·м⁻³ и центр масс в мм в model frame.
Актуальные overrides массы/центра отвергаются. При unknown сохраняется hold
через restart; не повторять расчёт. timeout не отменяет COM, ждать job_get.
Повтор того же request_id возвращает одно и то же задание.

Сборки, произвольные coordinate frames, габариты и расстояния этим scope
не поддерживаются. Selected UI objects должны иметь native PID roundtrip;
неадресуемое выделение отвергается до первой записи. Лимит:500 solid-тел.
# Габариты в явных осях

`measurement_get_bounds` измеряет все solid/surface-тела детали (body_type=all),
фильтр solid/surface или один persistent body_id; скрытые тела включены.
Нужны document_id/configuration/expected_observation_revision и request_id.
Чтение не меняет выделение, UI или модель. Native GetExtremePoint вызывается
в ±направлениях каждой оси, повторные extrema и полный body roster проверяются.
Approximate GetBodyBox не используется для этих измерений.

coordinate_frame=None означает модель. Явный frame содержит origin_mm и три
axes_in_model: p_model_mm=origin_mm+Σ(axis_i*p_frame_mm[i]). Оси ортонормальны,
правые; scale/shear/reflection запрещены. Возвращаются min_mm/max_mm/size_mm
в выбранных осях, не автоматически минимальный по объёму ориентированный box.
Чрезмерный offset, теряющий точность размера, отвергается. Лимит500 BREP-тел;
mesh/assembly/instance paths и native named-coordinate features пока вне scope.

# Каталог экземпляров сборки

`component_list` и `component_get`: явная сборка/активная конфигурация/observation_revision,
opaque component_id, полный native path, referenced configuration и transform к root assembly.
`component_body_list` и `component_body_get`: normal solid/surface тела конкретного
экземпляра детали; body_id действует только с исходным component_id. Координаты
приблизительных bounding boxes локальные, в мм; transform исключает presentation.
Только полностью resolved native экземпляры, без SpeedPak/mesh/assembly-cut user bodies;
suppressed/lightweight отвергаются без автоматического разрешения. Выделение/модель
не изменяются. Страницы сверяют полный состав/метаданные/transform, бюджет100000
компонентов, не более500 тел на экземпляр. Это не приёмка производительности1000+.
Приёмка этой области фиксируется в COMPONENT_READS_ACCEPTANCE.md.

# Геометрия конкретного экземпляра

`component_face_list`, `component_edge_list`, `component_topology_get` читают
normal native solid/surface тело по явным component_id/body_id в root сборке
и её активной конфигурации. Opaque object_id содержит исходную native связь
с этим экземпляром/телом. Native owner/membership и полный instance/body/topology
snapshot сверяются повторно, включая страницы; selection/model не меняются.
Area mm2, length/endpoints component-local mm, transform к root отдельно.
Start/end могут совпадать на замкнутой кривой. Изменение/удаление/замена/чужие
объекты не перепривязываются. Cursor связан с configuration/instance/body/kind.
Это observation read scope, не полный BREP certificate/revision для мутации.
Наследуются ограничения resolved/normal bodies; нет auto resolve/activate/rebuild.


### Расстояние между экземплярами деталей

`measurement_get_component_distance` принимает явные document_id, активную
configuration, expected_observation_revision и два разных component_a_id /
component_b_id из component_list. Native ClosestDistance учитывает трансформации
вложенных и повернутых экземпляров, normal solid тела, включая скрытые. Возвращает
расстояние и две ближайшие точки в мм в системе assembly_model. Surface тела
не входят в измерение. Подсборка как цель и неподдерживаемые состояния отклоняются.
Не меняет выделение и модели; ноль не классифицирует пересечение или вложение
материальных объёмов. Snapshot проверяет моменты тел, membership, конфигурации
и трансформации на обеих границах; это observation, не полная BREP revision.
Расстояния до точек/осей и native named frames пока не реализованы.


### Расстояние от экземпляра детали до точки

`measurement_get_component_point_distance`: explicit document/configuration/
expected_observation_revision/component_id, point_mm в root assembly или
переданной rigid frame (origin_mm, axes_in_model). Возвращает минимум до
индивидуальных solid boundary, nearest_mm в той же frame, root точки,
point_location (inside/outside/boundary) и исходные nearest_face_id/body_id.
Внутри расстояние остаётся положительным; native entry/exit rays заменяют
эвристику нормали. В boundary допуске0.00001 мм inside=null. Hidden normal
solids включены, surface исключены. Подсборки как цели, named native frames
и неподдерживаемые состояния не приняты. Closing gates включают all body/
face membership, summaries, geometric moments, configuration/transform;
это observation, не полная BREP mutation revision. UI/model не изменяются.


### Расстояние от экземпляра детали до оси

`measurement_get_component_axis_distance` требует root assembly/document,
активную configuration, observation_revision, component_id и request_id.
`axis_origin_mm` задаёт точку бесконечной прямой, `axis_direction` — конечный
ненулевой вектор; он нормализуется. Необязательный `frame` задаёт явные rigid
оси/начало в root assembly. Результат: distance_mm и две ближайшие точки в
входной frame и root assembly, normalized direction, infinite_line semantics.
Normal hidden solids включены, surface исключены. Exact GetExtremePoint
ограничивает временное ребро в памяти; в CAD-дерево ничего не вставляется,
выделение/активация/rebuild не выполняются. Zero не классифицирует пересечение.
Подсборки как агрегат, named native frames и unresolved/assembly-cut/mesh/SpeedPak
состояния ещё не поддерживаются. Это read-scope, а не полная BREP mutation revision.


### Расстояния агрегатов подсборок

`measurement_get_component_aggregate_distance` принимает две явные цели
part/subassembly в root assembly с configuration/observation_revision/request_id.
Выбираются все part leaves проверенной native parent иерархии. Измеряется минимум
каждой пары solid leaves, включая скрытые экземпляры/тела; surface-only и empty
leaves учитываются в census, но исключаются из минимума. Общий экземпляр в обеих
целях даёт ноль с native solid support witness. В результате присутствуют исходные
цели и nearest leaf IDs, body/leaf counts, обе ближайшие точки в root assembly и
необязательной explicit rigid frame. Ноль не классифицирует interference.
Нет selection/activation/rebuild, bbox fallback или неполного результата.
Бюджеты:1000 leaves на цель,5000 normal bodies суммарно,10000 leaf pairs.
Unsupported unresolved/SpeedPak/mesh/assembly-cut states и native named frames
ещё не поддержаны. Scoped read snapshots не заменяют полную BREP mutation revision.
